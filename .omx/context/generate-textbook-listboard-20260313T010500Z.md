# Context Snapshot — generate-textbook-listboard

- Task statement: Plan a refactor/extension of the 문제생성 area so that personal passages keep the current AI generation component, while non-personal textbook/exam-style menus use a copied-and-modified `textbook_generate` flow and first land on a `textbook_listboard` page.
- Desired outcome: A team-reviewed implementation plan covering route/component split, initial 모의고사 listboard UX, DB schema additions for 2-depth listboards and listboard posts, and a recommendation on whether the current `system_settings.header_navigation` JSON should remain or move to relational tables/FKs.
- Known facts/evidence:
  - Header menu config is stored in `public.system_settings` row `key='header_navigation'` and consumed by `src/lib/header-navigation-server.ts`.
  - Generate area uses `src/app/(dashboard)/generate/layout.tsx`, `generate-sidebar.tsx`, `page.tsx`, `[typeId]/page.tsx`, `[typeId]/generate-client.tsx`, and `multi/*`.
  - 2-depth menu links currently come from header navigation JSON and are rendered by `GenerateSidebar`.
  - Current single-type generation page fetches a `problem_types` row by route param and mounts `GenerateClient`.
  - `problem_types` is an existing table; `system_settings` is a generic JSON settings table with admin-only RLS.
- Constraints:
  - Personal-passage flow should keep the current AI generation component as-is first.
  - Other generate submenus should use a copied variant named `textbook_generate`.
  - Non-personal submenus should first open a `textbook_listboard` page instead of generation directly.
  - First implementation target is `모의고사` with filters: 년도, 월, 학년 dropdowns + 제목 keyword.
  - Need DB tables for each listboard (2-depth menu) and posts registered under those boards.
  - Need architectural review of tying listboards to header/menu config, including whether JSON-in-settings remains valid.
- Unknowns/open questions:
  - Exact canonical route scheme for personal vs board/listboard flows.
  - Whether menu slugs should be derived from header config or owned by new relational tables.
  - Whether existing `problem_types` should map to listboard/menu entities or stay separate.
  - Admin CRUD scope for listboards/posts in first slice.
- Likely codebase touchpoints:
  - `src/app/(dashboard)/generate/**`
  - `src/app/(admin)/admin/menu-management/**`
  - `src/lib/header-navigation*.ts`
  - `src/types/supabase.ts`
