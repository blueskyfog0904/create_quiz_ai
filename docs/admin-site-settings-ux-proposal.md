# 관리자 "사이트 기본 정보" 화면 개선안과 화면 공통 점검 기준 (초안)

작성일: 2026-11-23 · 화면: `/admin/footer` (`src/app/(admin)/admin/footer/*`) · 브라우저로 직접 확인함

## 1. 지금 화면의 문제 (실제 화면 기준)

한 화면에 성격이 다른 설정 6덩어리가 위에서 아래로 이어져 있다(스크롤이 매우 김).

| 순서 | 덩어리 | 저장 방식 | 문제 |
|---|---|---|---|
| ① | 사이트 이름·소개 | 자체 "사이트 이름 저장" | — |
| ② | 사이트 로고 | 자체 "로고 저장 및 적용" | — |
| ③ | 가입 동의 항목(대표 전용) + 안내 문구 9칸 | 항목은 행마다 수정, 안내 문구는 "안내 문구 저장" | 화면 중간에 큰 표와 긴 입력칸 9개가 끼어 아래 하단 정보까지 멀어짐 |
| ④ | 기본 사업자 정보 10칸 | **맨 위 "하단 정보 저장"** | 칸마다 테두리 상자 한 줄씩이라 세로로 매우 김. 저장 버튼이 화면 맨 위(①보다 위)에 있어 어느 것을 저장하는지 알기 어렵고, 고친 뒤 위로 올라가야 함 |
| ⑤ | 추가 안내 문구 | ④와 같은 버튼 | 같음 |
| ⑥ | 약관 및 정책(문서 3개, 12줄 입력칸) + 미리보기 | ④와 같은 버튼 | 문서 3개가 위아래로 쌓여 가장 긴 부분. 문서 하나만 고칠 때도 셋을 지나가야 함 |

공통 문제
- **저장 범위가 섞임**: 저장 버튼이 5개이고, 그중 하나(맨 위)는 ④⑤⑥ 세 덩어리를 함께 저장한다. 어떤 입력이 어느 버튼으로 저장되는지 화면에서 드러나지 않는다.
- **안 저장된 변경 표시 없음**: 아래쪽을 고치고 다른 덩어리의 저장 버튼을 누르면 고친 내용이 저장되지 않은 채 남는다.
- **위치 이동 수단 없음**: 덩어리 사이를 건너뛸 목차·탭이 없다.
- **쓰는 빈도가 섞임**: 자주 고칠 일(이름·로고·약관)과 거의 안 고칠 일(사업자 정보), 대표만 볼 일(가입 동의)이 같은 화면에 같은 무게로 놓여 있다.

## 2. 개선안

### 2-1. 화면을 탭으로 나눔 (주소에 탭 기억: `/admin/footer?tab=…`)
| 탭 | 담는 것 | 저장 |
|---|---|---|
| **브랜드** | 사이트 이름·소개, 로고 | 각자 저장(지금처럼) |
| **사업자·하단 정보** | 법정 표시 항목(2열 표 형태로 촘촘하게), 추가 안내 문구, 하단 미리보기 | 탭 아래 고정 저장 바 |
| **약관 및 정책** | 문서별 하위 탭(이용약관·개인정보처리방침·취소/환불정책), 문서마다 본문 편집 + 미리보기(회원 화면과 같은 렌더러), "약관 이력 보기" | 탭 아래 고정 저장 바 |
| **가입 동의** (대표만 보임) | 동의 항목 표, 안내 문구(접어 두기) | 항목은 행마다, 안내 문구는 자체 저장 |

### 2-2. 저장 규칙 하나로
- 한 탭(또는 한 카드)에는 저장 버튼 하나. 저장 버튼은 **그 내용 바로 아래 또는 화면 아래 고정 바**에 둔다(맨 위에 두지 않음).
- 고정 저장 바: "저장하지 않은 변경 n건 · 되돌리기 · 저장". 변경이 없으면 숨김.
- 다른 탭으로 옮기거나 페이지를 떠날 때 저장 안 된 변경이 있으면 확인 창.

### 2-3. 입력 모양
- 짧은 값(상호·대표자·번호)은 2열 그리드, 한 줄 라벨. "법정 표시 항목·끌 수 없음"은 칸마다 반복하지 않고 라벨 옆 작은 표시.
- 긴 본문(약관)은 문서 하나만 보이게(하위 탭) + 입력칸 높이를 화면에 맞춤.

### 2-4. 순서
1. 탭 나누기와 저장 바(이 화면) → 2. 같은 틀을 19번 묶음 "관리자 공통 틀"(저장 바·필터 줄·공통 확인 창)의 첫 적용으로 삼아 다른 화면에 넓힘.

## 3. 다른 화면 점검 기준 (이 개선안에서 뽑음)
- A. **한 화면 과밀**: 성격·사용 빈도·권한이 다른 덩어리가 한 화면에 길게 나열되어 있는가 → 탭·하위 페이지로 나눌 대상
- B. **저장 범위 불명확**: 저장 버튼이 여럿이거나, 버튼과 그것이 저장하는 입력이 멀리 떨어져 있는가(맨 위 저장 등)
- C. **안 저장 변경 표시·이탈 경고 없음**
- D. **이동 수단 없음**: 긴 화면에 목차·탭·앵커가 없는가
- E. **입력 밀도**: 짧은 값이 한 줄씩 큰 상자로 세로로 길게 놓였는가 / 긴 본문 여러 개가 한 번에 펼쳐져 있는가
- F. **권한·위험 구분**: 대표 전용·되돌릴 수 없는 동작이 일반 설정과 섞여 같은 무게로 보이는가
- G. **표·목록**: 필터·검색·페이지 나누기가 없거나 한 줄에 정보가 너무 적은가(기존 `docs/admin-ux-improvement-plan.md` 지적과 겹치면 그 번호를 적음)

## 4. 다른 화면 점검 결과 (2026-11-23, 화면 22개 · 점검 3명 → 코드 반박 검증 3명, 확인 29건 · 기각 7건)

### 4-1. 먼저 고칠 "입력이 사라지는" 문제 (데이터 유실, 화면 구조와 별개)
| 화면 | 문제 | 고칠 방향 |
|---|---|---|
| 상품 등록·수정 | 서브상품 추가·저장·삭제, 파일 업로드·제거는 바로 저장되고, 그 뒤 서버 값을 다시 읽으며 **저장 전인 '전체 한번에 구매하기' 설정(켜기·가격)을 원래대로 덮어씀**. 모르고 공개하면 전체구매가 꺼진 채·예전 가격으로 판매. '저장됨' 배지도 입력값과 무관하게 표시(market-products-client.tsx 985-997, 1142-1152, 2725) | 다시 읽어도 사용자가 고친 값은 남김, 배지는 입력=서버 값일 때만, 판매 구성 구역 저장 방식 하나로 |
| 메뉴관리 | 한 영역을 저장하면 다른 영역의 저장 안 한 변경이 지워짐, 국어/영어 전환 때 저장 안 한 변경이 경고 없이 사라짐(관리자 사이드바 순서 포함) | 탭 분리(관리자 메뉴 순서 / 옛 회원 헤더), 전환·이탈 경고 |
| 후기 태그 | 한 행을 저장·비활성화·추가하면 다른 행의 고친 값이 모두 되돌아감 | 표 전체 편집 + 저장 바 하나 |
| 카테고리 편집기 | 같은 칸에서 이름·순서를 고친 뒤 이미지·활성을 바꾸면 고친 이름·순서가 되돌아감 | 즉시 저장 뒤에도 같은 칸 초안 유지 |
| 관리자 ID | 다른 관리자 비밀번호 재설정·새 계정 추가가 가려진 칸 하나 + 확인 없이 바로 적용(오타면 그 계정이 잠김) | 작은 창 + 확인 칸, 실행 버튼 |

### 4-2. 화면 구조(이 개선안의 탭·저장 바 틀을 넓힐 곳)
| 화면 | 할 일 |
|---|---|
| 사이트 기본 정보 | 2절 개선안(탭 4개·저장 바) — 공통 틀의 첫 적용 |
| 요금제 | 탭 [요금제 \| 충전 화면 문구], 문구 탭에 저장 바. 충전 화면 문구가 비거나 깨져 결제가 막히면 제목 아래 빨간 띠 |
| 환불 | 탭 [문제마켓 환불(기본) \| 충전 환불 \| 결제 확인], 통계 카드에 '충전' 범위 표시, 마켓 환불에 필터·쪽 넘김·대기 건수, 탭과 필터를 주소에 기억 |
| 고객지원 | 탭 [문의 \| 카테고리 관리](주소 기억), 건수 카드에서 설정 숫자 빼기, 필터 한 줄(바로 반영) |
| 메뉴관리 | 탭 [관리자 메뉴 순서 \| 옛 회원 헤더(고급 접기)] |
| 메인광고 | 아래 고정 저장 바(홈 진열 화면의 저장 바를 가져다 씀), 오류 카드로 이동, 광고 추가 뒤 새 카드로 이동 |
| 회원 상세 | 요약 띠 + 탭(기존 계획 D-07), 문의 링크에 회원 조건(?q=이메일) |
| 상품 목록 | '수정'을 누르면 폼으로 이동(지금은 반응 없어 보임), 폼을 넓게(기존 B-09·C-03 별도 주소까지) |
| 상품 등록 | 전역 설정(카테고리 트리·서브상품 카테고리·파일 유형)을 별도 관리 화면으로, 상품 폼엔 선택칸 + '설정 화면에서 관리' 링크 |
| 작업 기록 | 상세를 '변경 전 → 후' 표로, 원본 JSON 은 접기 |
| 약관 이력 | 문서별 거르기 + '현재 시행 중' 표시 |

### 4-3. 공통 규칙(19번 '관리자 공통 틀'로 묶음)
1. **탭과 필터는 주소에 기억**(?tab=·?doc=·필터) — 새로고침·뒤로 가기·다른 화면에서 들어올 때 그 자리로.
2. **저장 바 하나**: "저장 안 한 변경 n건 · 되돌리기 · 저장"을 아래 고정, 변경 없으면 숨김, 탭 이동·과목 전환·페이지 이탈 때 확인 창(지금 저장소 전체에 이탈 경고가 한 곳도 없음).
3. **다시 읽어도 사용자가 고친 값은 남김**(즉시 저장 뒤 서버 값으로 덮어쓰지 않음).
4. **한 구역에 저장 방식 하나**, 아니면 '바로 저장됨' 표시.
5. **알림 문구**: 저장 전에는 "목록에 반영 · 저장해야 적용", 저장 뒤에만 "저장했습니다".
6. **위험 동작**: 공통 확인 창(브라우저 confirm 대신), 되돌릴 수 없는 동작은 같은 빨간 색·같은 문구 규칙(실제로 숨김이면 '숨김').
7. **누른 결과가 화면 밖이면 그리로 이동**(폼 열기·항목 추가·오류 위치).
8. **개발 용어는 '고급' 접기**(slug·코드·MIME·source mode·원본 JSON 등), 아이콘 버튼엔 이름표.
9. **필터 모양 하나**: 한 줄, 선택은 바로 반영, 검색만 Enter.

### 4-4. 제안 순서
1. **4-1 데이터 유실 5건 먼저**(작은 수정, 출시 전 상품 재정리 때 바로 영향 — 특히 상품 등록).
2. **공통 틀 부품**: 주소 탭, 저장 바 + 이탈 경고, 공통 확인 창, 필터 한 줄.
3. **적용**: 사이트 기본 정보 → 요금제·환불·고객지원 → 메뉴관리·메인광고 → 회원 상세·작업 기록·약관 이력.
