# 회원 화면 요소 관리자 관리 개선 계획

작성일: 2026-11-20
조사 방법
- 에이전트 3개가 영역을 나눠 코드를 읽었습니다.
  - A: 공통 틀·홈·탐색
  - B: 상품 탐색·상세·구매
  - C: 회원·결제·마이페이지
- 핵심 지적 3건은 직접 다시 확인했습니다.
  - 회원가입 약관 동의 항목이 없음
  - 메뉴관리의 상단 메뉴가 실제 회원 헤더에 반영되지 않음
  - 상품 출처 입력칸이 없음

기준(하드코딩 금지 규칙)
- 운영 문구와 데이터(안내·정책 설명·섹션 제목·선택지 목록·알림 문구)는 DB에 두고 관리자에서 고칩니다.
- 화면 조작 문구("확인", "취소", "장바구니")와 레이아웃은 코드에 둬도 됩니다.
- 환불 기간, 사용 기한 같은 정책 값은 글자로 고치게 하지 않습니다. DB 판정 함수가 기준이고, 문구에는 자리표시(`{환불기간}` 등)로 끼워 씁니다. 지금 충전 화면 문구가 이 방식입니다.

## 1. 지금 상태 요약

### 이미 잘 관리되는 것
| 회원 화면 | 관리자 메뉴 | 되는 것 |
|---|---|---|
| 홈 메인 배너 | 홈 배너 | 추가·삭제·순서·숨김·이미지·링크·노출 시간 |
| 카테고리 메뉴와 목록 | 카테고리 | 추가·이름·순서·숨김·삭제·기본 이미지 |
| 상품 제목·요약·설명·이미지·가격·파일·샘플 | 상품 관리 | 대부분 |
| 서브상품 이름(구성 배지), 파일 유형 이름 | 상품 관리 안 설정 창 | 추가·수정·순서·숨김·삭제 |
| 후기 태그 | 후기 태그 | 추가·수정·순서·숨김 |
| 충전 화면 문구와 충전 상품 | 요금제 | 거의 전부 |
| 문의 카테고리와 작성 안내 | 고객지원 | 추가·수정·숨김·순서 |
| 사업자 정보, 약관 본문 | 하단 정보 | 값 수정·숨김 |

### 관리가 안 되거나 고장 난 것(핵심)
1. **회원가입에 약관·개인정보 동의 항목이 아예 없습니다.** 동의 기록을 남기는 DB 칸도 없습니다. 법적 위험이 큽니다.
2. **메뉴관리에서 저장한 상단 메뉴와 "로고 문구"가 실제 회원 화면에 반영되지 않습니다.** 회원 화면 헤더(`preview-header.tsx`)가 그 설정을 읽지 않고, 옛 헤더만 읽습니다. 사이트 이름 "써머썬 연구소"는 헤더와 브라우저 탭 제목 약 24곳에 코드로 박혀 있습니다.
3. **상품 상세에 보이는 "출처"를 관리자에서 입력할 칸이 없습니다.**
4. **선택지 목록이 코드나 자유 입력입니다.**
   - 학년 선택지 ["1학년", "2학년", "3학년"]은 코드 상수입니다.
   - 자료유형은 자유 입력이라 오타와 표기 차이가 생깁니다.
   - 검색 필터의 "자료유형"은 상세의 "자료유형"과 다른 값(서브상품 구성)을 가리킵니다.
5. **관리자가 바꾸면 사이트가 고장 나는 칸이 열려 있습니다.**
   - 서브상품 카테고리의 slug(`question_hwp`·`question_pdf`)
   - 파일 유형의 code(`pdf`·`hwp`·`zip`)
   - 코드가 이 값에 기대고 있습니다.
6. **결제·환불 안내가 네 곳에 흩어져 있고, DB로 관리되는 것은 충전 화면 한 곳뿐입니다.**
   - 결제 화면 "결제 전 확인" 3줄
   - 크레딧 환불 안내
   - 약관 페이지의 "포인트 충전 핵심 안내" 보충 칸(결제수단 목록 포함)
   - 문제마켓 자료 환불 기간 7일은 코드 숫자 하나뿐입니다.
7. **회원에게 가는 알림 문구 8종이 코드 10곳에 흩어져 있습니다**(같은 문구가 중복된 곳 포함). 운영자가 공지 알림을 보낼 기능도 없습니다.
8. **홈 섹션 제목·빈 화면 문구·섹션 순서가 코드에 있습니다.** 추천 자료를 직접 골라 진열하는 기능도 없습니다.
9. **상품 상세의 운영 안내 문구가 코드에 있습니다.**
   - 구매 하단 안내, 샘플 안내, HWP+PDF 기본 안내가 해당합니다.
   - 샘플 안내 "구매 전 PDF **첫 N쪽**"은 실제와 다를 수 있습니다(샘플을 1, 5, 7쪽처럼 고를 수 있음).
   - 전체구매 제목은 "전체 패키지"로 고정입니다. 관리자가 입력한 "표시명"은 상세에 나오지 않습니다.
10. **일부만 되는 관리 기능**
    - 서브상품 노출 순서를 바꿀 수 없습니다.
    - 후기는 삭제만 됩니다(숨김·복구 없음).
    - 숨긴 문의 카테고리를 되살릴 수 없습니다.
    - 문의 답변을 고칠 수 없습니다.
    - 하단 정보의 추가 안내 문구 순서를 바꿀 수 없고, 약관은 3종 고정입니다.

## 2. 개선 방향

### 2-1. 원칙
- **그 화면을 관리하는 메뉴에서 그 화면의 문구도 고칩니다.** 예를 들어 상품 상세 안내는 마켓의 "상품 표시 설정"에서 고치고, 결제 안내는 "요금제"에서 고칩니다. 문구를 한곳에 몰아 두는 별도 메뉴는 만들지 않습니다.
- **저장 방식은 지금 충전 화면 문구와 같습니다.**
  - 화면마다 설정 키 하나에 JSON으로 저장합니다(공통은 `system_settings`, 과목별은 `workspace_settings`).
  - 처음 값은 마이그레이션으로 DB에 넣습니다. 코드에 기본 문구를 두지 않습니다.
  - 값이 없거나 깨졌을 때는 다르게 처리합니다. 결제·환불·법적 안내는 해당 동작(결제·가입)을 막고, 나머지는 그 칸만 숨깁니다.
- **꺼 둔 표기값 기능(`/admin/labels`)은 되살리지 않습니다.** 화면별 설정이 고치기 쉽고 실수가 적습니다.
- **고장 위험이 있는 칸은 잠급니다**(slug, code, 결제수단 코드). 이름과 설명만 고칠 수 있게 합니다.

### 2-2. 관리자 메뉴 배치(지금 사이드바 기준)
| 사이드바 | 추가·변경 | 관리할 회원 화면 요소 |
|---|---|---|
| 국어/영어 마켓 › 홈 배너 | 예약 노출(시작·종료 일시), 배너가 없을 때 영역 숨김 | 홈 배너 |
| 국어/영어 마켓 › 홈 진열 | 섹션 목록: 추가·삭제·순서·숨김·제목·빈 화면 문구, **추천 자료 직접 진열** 섹션 | 홈 섹션 |
| 국어/영어 마켓 › 상품 관리 | 출처 1~4 입력칸, 학년·자료유형을 목록에서 고르기, 서브상품 순서 변경, 전체구매 표시명 정리 | 상품 상세 자료 정보·구매 영역 |
| 국어/영어 마켓 › **상품 표시 설정(신설)** | 학년 목록, 자료유형 목록, 서브상품 구성·파일 유형(지금 상품 화면 안 설정 창을 옮김, slug·code 잠금), 검색 필터 이름·숨김·순서, 상세 안내 문구(구매 하단·샘플·HWP+PDF 기본), 자료 정보 항목 이름·숨김·순서 | 검색, 상품 상세, 상품 목록 |
| 국어/영어 마켓 › 후기 | 숨김·숨김 해제, 삭제된 후기 복구, 작성자 역할 이름은 DB 값 사용 | 후기 |
| 주문·결제 › 요금제 | 결제 화면 문구, 크레딧 환불 안내, 결제수단 이름·설명·순서·사용(코드는 잠금), 확인 사항 순서 변경 | 결제 화면, 크레딧 관리, 약관 보충 칸 |
| 회원·고객 › 고객지원 | 안내 문구 탭(상단 안내·접수 완료), 숨긴 카테고리 복구, 답변 수정 | 고객지원 |
| 회원·고객 › **알림(신설)** | 알림 문구 8종 수정·끄기(추가·삭제는 막음), 공지 알림 보내기(전체/선택 회원) | 알림 종, 알림 화면 |
| 회원·고객 › 회원 | 탈퇴 화면 문구(경고·동의 항목·불가 안내) | 회원 탈퇴 |
| 사이트 설정 › **사이트 기본 정보**("하단 정보"를 넓힘) | 사이트 이름, 브라우저 탭 제목·설명, 로고(메뉴관리에서 옮김, 기본 로고로 되돌리기), 사업자 정보(법정 항목은 끌 수 없음), 항목 이름, 추가 안내 순서, 약관 추가·순서·시행일, **가입 동의 항목** | 헤더 이름, 탭 제목, 하단, 약관, 회원가입 |
| 사이트 설정 › **상단 메뉴(신설)** | 회원 헤더 2단 메뉴 링크 추가·수정·삭제·순서·숨김("크레딧 충전" 포함). 카테고리·국어·영어 탭은 구조라 코드에 둠 | 회원 헤더 |
| 사이트 설정 › 메뉴관리 | 옛 헤더 설정 부분 정리(개발 용어 제거). 관리자 사이드바 순서만 남김 | – |

## 4. 대표가 정해 주실 것
1. **회원가입 약관 동의 구성**
   - 필수 항목은 이용약관과 개인정보 수집·이용 2개로 할까요? 마케팅 수신 같은 선택 항목도 둘까요?
   - 이미 가입한 회원은 다음 로그인 때 동의를 받을까요?
2. **약관 문구 확인**
   - 약관 보충 문장: "이용기간과 환불가능기간은 결제시점으로부터 1년 이내"
   - 결제 화면 문장: "7일 이내 완전 미사용 시 환불"
   - 두 문장이 함께 보입니다. 어느 쪽이 맞는 정책인지 확인이 필요합니다.
3. **전체구매 제목**
   - (가) 관리자가 입력한 "표시명"을 상세에도 쓰고, 비어 있으면 "전체 패키지"로 둔다
   - (나) 표시명 칸을 없애고 한 가지 이름으로 통일한다
4. **공지 범위**: 알림 종으로 공지만 보내면 될까요, 공지 게시판(목록 화면)까지 필요할까요?
5. **홈 추천 자료**: 대표가 직접 고른 자료를 홈에 진열하는 섹션이 필요할까요?
