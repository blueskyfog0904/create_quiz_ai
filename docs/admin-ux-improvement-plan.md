# 문제마켓 관리자 화면 개선 계획

## 1. 한 줄 요약과 지금 상태

**한 줄 요약:** 관리자 화면의 공통 틀(표, 저장 바, 확인 창, 색)을 먼저 하나로 만듭니다. 그 틀 위에서 대시보드를 그래프 중심으로 바꾸고, 상품 등록을 "실수 막기 → 반복 줄이기" 순서로 고칩니다.

**지금 상태**
- 화면마다 따로 만들어져 공통 틀이 없습니다. 제목 모양 4가지, 저장 버튼 위치 4가지, 상태 색, 금액·날짜 표기가 화면마다 다릅니다.
- 대시보드는 숫자를 글자로만 보여 줍니다. 그래프, 기간 선택, 지난 기간과의 비교, 문제마켓 판매·상품 현황이 없습니다.
- 상품 등록은 5단계 틀은 갖췄습니다. 하지만 구매할 수 없는 상품이 공개되는 길이 3개 있습니다(0크레딧, 파일 즉시 삭제, 숨김 뒤 다시 공개). 저장 안 된 변경도 알려 주지 않습니다.
- 상품 148개 대부분이 같은 구성인데 복제·이어받기 기능이 없습니다. 그래서 상품 하나에 25번 넘게 조작합니다.
- 안전장치의 기본(지급·회수 2단계 확인, 조회 실패와 0건 구분, 판매 중지는 대표만)은 잘 되어 있으니 그대로 둡니다.

## 2. 관리자 화면 설계 원칙(12개)

| # | 원칙 | 구체 규칙 |
|---|---|---|
| 1 | 하는 일 기준으로 메뉴를 묶는다 | 왼쪽 메뉴는 6묶음(운영 / 상품 / 홈 화면 / 회원·크레딧 / 후기 / 설정)에 2단까지만 둡니다. 묶음의 첫 항목은 가장 자주 하는 일입니다(상품 묶음은 상품 목록 → 상품 등록). 메뉴 이름은 4~8자로 하고, 묶음 이름을 하위 메뉴에서 되풀이하지 않습니다. 처리할 건수는 메뉴 옆 숫자로 보여 주고 0이면 감춥니다. 메뉴 이름과 순서는 DB에서 바꿉니다. |
| 2 | 과목(국어/영어)은 한 곳에, 늘 보이게 | 과목 전환기는 과목 전용 화면(상품·카테고리·홈 화면·후기)의 제목 옆에만 둡니다. 주문·회원·환불 같은 공통 화면에는 과목 표시를 하지 않습니다. 화면 사이 링크는 모두 과목 값을 들고 다닙니다. 상품 저장 버튼에도 과목을 적습니다("국어 상품으로 공개"). |
| 3 | 모든 화면은 같은 뼈대 | 위에서부터 제목줄 → 안내 띠 → 검색·필터 줄 → 본문 → 저장 바 또는 쪽 넘김 순서입니다. 제목은 24px 굵게, 설명은 한 줄입니다. 주요 버튼은 제목줄 오른쪽에 1개만 둡니다. 바깥 여백은 레이아웃 한 곳에서만 정합니다. |
| 4 | 표는 촘촘하게 | 행 높이 40px(조밀 모드 32px), 글자 13px입니다. 스크롤해도 표 머리는 고정합니다. 카드형 목록(회원·문의)은 표로 바꿉니다. 행을 누르면 상세가 열리고, 행 끝에는 버튼 1개와 "⋯" 메뉴만 둡니다. 체크하면 표 위에 일괄 작업 줄이 나타납니다. |
| 5 | 숫자는 한 가지 표기로, 오른쪽 정렬 | 금액은 "9,900원", 크레딧은 "3,000 C"입니다. 증감은 부호와 색을 함께 씁니다(+초록, −빨강). 목록의 날짜는 "11-19 10:44"(한국 시간, 24시간)로 쓰고, 마우스를 올리면 전체 시각이 보입니다. 숫자 열은 오른쪽 정렬에 자릿수를 맞춥니다. 값이 없으면 "–"로, 세지 못한 값은 0이 아니라 "확인 불가"로 씁니다. |
| 6 | 상태 색은 5가지만 | 회색(임시저장·만료), 파랑(처리 중·환불됨), 초록(완료·공개), 호박색(대기·확인 필요), 빨강(실패·거부)입니다. 연한 바탕에 진한 글자를 쓰고, 상태와 색의 대응은 한 파일에서만 정합니다. 같은 "환불 완료"는 어느 화면에서나 같은 색입니다. |
| 7 | 되돌릴 수 없는 동작은 확인 창 하나로 | 삭제, 숨김, 환불, 권한 해제, 판매 중지, 크레딧 회수가 대상입니다. 회원 화면과 같은 팝업 틀을 씁니다. 제목에는 대상과 개수, 본문에는 영향(상품 n개가 내려감, 금액은 굵게)을 적습니다. 실행 버튼 이름은 동작 이름 그대로("12개 숨기기")이고, 처리 중에는 버튼을 잠급니다. 브라우저 기본 경고창은 쓰지 않습니다. |
| 8 | 저장은 한 자리, 상태는 늘 보이게 | 입력 화면은 아래쪽 고정 저장 바 하나로 맞춥니다. 바에는 "저장 안 된 변경 3건 / 저장 중 / 14:02 저장됨 / 실패·다시 시도"를 보여 줍니다. 저장하지 않고 다른 화면으로 가거나 탭을 닫으면 경고합니다. 바로 반영되는 영역에는 "즉시 반영" 표시를 붙입니다. |
| 9 | 필터는 한 줄, 주소에 남게 | 한 줄에 검색 → 선택 필터 → 기간을 두고, 오른쪽에 "결과 n건"과 초기화를 둡니다. 필터 값은 주소에 남겨 새로고침·뒤로 가기·링크 공유 뒤에도 그대로 둡니다. 상태는 개수가 붙은 탭으로 보여 줍니다. |
| 10 | 비어 있음, 불러오는 중, 실패를 구분 | 불러오는 중에는 표 모양의 회색 뼈대를 보여 줍니다. 비어 있으면 이유와 다음 행동 버튼("필터 초기화", "상품 등록")을 둡니다. 읽기에 실패하면 무엇을 못 읽었는지와 "다시 시도"를 빨간 안내로 보여 줍니다. 비어 있음과 실패가 같은 모양이면 안 됩니다. |
| 11 | 대시보드는 그림 먼저, 표는 나중 | 기간 선택 → 핵심 지표 카드 4장 → 추이 그래프·비율 그래프 → 상품 순위 → 최근 목록 순서입니다. 처리할 일이 0건이면 한 줄로 접습니다. |
| 12 | 회원 화면과 같은 재료, 관리자다운 밀도 | 회원 화면의 색·글꼴·둥글기·팝업 틀(보라색 강조 하나)을 그대로 씁니다. 관리자용으로는 크기만 줄입니다(입력칸 32px, 표 행 40px). 주황 메뉴 강조, 남색·파랑 버튼은 없앱니다. 운영자에게 개발 용어(source mode, legacy, 권한 키 원문, 내부 이메일, 원본 JSON)를 보여 주지 않습니다. |

## 3. 대시보드 개편안

### 3-1. 화면 배치(위에서 아래로)

| 줄 | 왼쪽 | 오른쪽 |
|---|---|---|
| ① 제목줄 | "대시보드"(20px). 흔한 부제("서비스 현황을 한눈에…")는 지움 | [전체·국어·영어] 과목 필터, 기간 선택(오늘·7일·**30일(기본)**·이번 달·지난 달·직접 지정), 새로고침, "마지막 갱신 15:12" |
| ② 운영 상태 바(한 줄) | 0이 아닌 처리 대기만 색 칩으로 보여 줌(예: "마켓 환불 대기 2" → 누르면 그 화면). 모두 0이면 "처리할 일 없음" | "충전 판매 중 ●" 또는 "중지됨 ●", 대표 전용 [충전 판매 중지](지금의 확인 창 그대로), "슬랙 알림 ● 정상". 판매 중지나 결제 경보가 있으면 바 전체가 빨간 테두리 |
| ③ 핵심 지표 카드 4장(가로 4칸) | 순 충전 매출 · 마켓 판매 · 신규 가입 · 구매 파일 다운로드 | 카드를 누르면 ④의 그래프가 그 지표로 바뀜 |
| ④ 그래프 | (넓게, 2/3) 일별 추이 그래프 | (좁게, 1/3) 도넛 비율 그래프 |
| ⑤ 상품 | 판매 상위 5개 가로 막대(다운로드 상위 5개 탭) | 상품 현황 카드: 공개/임시저장/숨김 개수 막대, "게시 대기 n개", 최근 수정 3개, [상품 등록] |
| ⑥ 최근 목록(탭 표) | [최근 마켓 구매 \| 최근 충전 주문 \| 답변 대기 문의] | 촘촘한 표(행 36px, 금액 오른쪽 정렬, 상태 색 배지) |

### 3-2. 핵심 지표 카드 정의

공통 규칙은 다음과 같습니다.
- 기간 경계는 한국 시간 자정입니다.
- "집계 제외 계정"(관리자·테스트 계정)은 DB에 적힌 표시로 판정하고, 코드에 계정을 적지 않습니다.
- 카드마다 들어가는 것: 큰 숫자 = 선택한 기간 값, 둘째 줄 = 지난 같은 길이 기간과의 증감(▲▼와 색), 셋째 줄 = 오늘 값. 지금처럼 오늘 값을 크게, 이번 달 값을 작은 회색으로 쓰는 위계를 뒤집습니다.
- 지난 기간이 0이면 %를 내지 않고 "이전 0 → 신규"로 적습니다("+∞%"는 쓰지 않음).

| 카드 | 계산 방법 | 보조 줄 | 볼 수 있는 사람 |
|---|---|---|---|
| 순 충전 매출(원) | 기간 안에 승인된 **실결제** 충전액 − 기간 안에 완료된 **실결제** 환불액 | "결제 n건 X원 · 환불 m건 Y원" | 주문 보기 권한 |
| 마켓 판매(건 · C) | 기간 안 완료된 마켓 구매 건수와 사용 크레딧 합계. **집계 제외 계정 제외**, 과목 필터를 따름 | "환불·회수 n건" | 주문 보기 권한 |
| 신규 가입(명) | 기간 안 가입자. 집계 제외 계정 제외 | – | 회원 보기 권한(없으면 카드 숨김) |
| 구매 파일 다운로드(회) | 기간 안 다운로드 중 샘플이 아닌 것. 집계 제외 계정 제외 | "샘플 n회" | 주문 보기 권한 |

> 참고: 지금은 충전 결제·환불만 테스트 결제를 빼고, 마켓 판매·다운로드는 관리자·테스트 계정을 가리지 않고 다 셉니다(A-03). 다운로드에 샘플이 섞이는지는 아직 실제 데이터로 확인하지 못했습니다. 개발 때 확인한 뒤 나눕니다. 상세 화면 조회수는 로그인 회원만 기록되므로 카드에는 넣지 않습니다.

### 3-3. 그래프

| 그래프 | 내용 | 규칙 |
|---|---|---|
| 일별 추이 | 고른 카드의 하루 단위 값. 매출을 고르면 결제는 막대, 환불은 아래쪽 막대(주황), 순매출은 선 | 기준 축은 하나만 씁니다. 지난 기간은 옅은 점선으로 겹칩니다. 90일이 넘으면 주 단위로 묶습니다. |
| 도넛 비율 | 기본은 "마켓 판매 크레딧 구성 = 과목(국어/영어) × 구매 방식(낱개/전체구매)". 탭을 바꾸면 "충전 요금제별 결제액" | 가운데에 합계를 쓰고, 범례에 값과 %를 함께 적습니다. |
| 판매 상위 5개 | 상품별 완료 건수·크레딧(탭: 다운로드 상위 5개) | 막대를 누르면 그 상품의 수정 화면으로 갑니다. |
| 상품 현황 | 공개·임시저장·숨김 개수를 쌓은 막대 하나 | 임시저장이 있으면 "게시 대기 n개"를 보라색으로 강조합니다. |

**그래프 도구:** 지금은 그래프 도구가 설치되어 있지 않습니다. 추천은 Recharts 하나입니다. 회원 화면 색을 그대로 쓸 수 있고, 꺾은선·막대·도넛·설명 말풍선을 모두 지원합니다. 대시보드에서만 불러오므로 다른 화면 속도에는 영향이 없습니다. 따로 의견이 없으시면 이것으로 진행합니다.

### 3-4. 데이터를 모으는 방법과 안전장치
- 하루 단위 집계는 DB에 "읽기 전용 집계 함수" 하나를 새로 만들어 처리합니다. 지금 방식(이번 달 행을 모두 읽어 더하기)으로는 90일 추이를 감당할 수 없습니다.
- **안전장치(A-01 위험 확인 결과)**
  - 새 집계 함수는 일반 회원·비로그인 사용자가 부를 수 없게 막고, 서버만 부르게 합니다.
  - 서버에서 권한을 확인한 뒤에만 부릅니다.
  - 충전은 "실결제만" 조건을 그대로 둡니다.
  - 직접 지정한 기간은 날짜 형식과 최대 범위를 서버에서 검사합니다.
  - 결제 관련 DB 변경이므로 결제 DB 전문 검증을 거칩니다. 앞 코드를 배포한 뒤에 적용합니다.
- 새로 넣는 최근 마켓 구매·판매 순위는 주문 보기 권한이 있을 때만 읽습니다. 상품 현황·[상품 등록]은 상품 편집 권한이 있을 때만 보입니다(A-02).

### 3-5. 출시 초기, 데이터가 거의 없을 때
- 날짜마다 0을 채워 그리므로 축과 기준선은 늘 보입니다. 합계가 0이면 그래프 가운데에 옅게 "이 기간 판매 없음"이라고 씁니다.
- 도넛이 모두 0이면 회색 고리와 "데이터 없음"을 보여 줍니다. 순위가 비면 "판매된 상품 없음 · 공개 상품 n개"와 [상품 등록] 버튼을 보여 줍니다.
- 새로고침 중에는 숫자를 지우지 않고 버튼만 돕니다. 지금은 화면 전체가 회색 뼈대로 바뀝니다(A-07).

## 4. 상품 업로드 개선안(핵심)

### 4-1. 단계 흐름 전/후 비교

| 단계 | 지금 | 바꾼 뒤 |

### 4-2. 수정 화면 배치
- 수정은 별도 주소로 엽니다(C-03, B-09). 위쪽에 "목록으로"와 "이전/다음 상품"을 두고, 목록으로 돌아오면 필터와 위치가 그대로 있게 합니다.
- 제목줄에는 상태 배지, 공개일·최근 수정일, [상세 페이지 보기], 판매 수를 한 줄로 둡니다.
- 왼쪽은 촘촘한 입력 영역입니다. 오른쪽 360px 고정 요약판에는 상품 카드 미리보기, 판매 구성 요약, 샘플 장수, 공개 전 점검, 저장 상태를 둡니다.
- 공개 중인 상품의 판매 구성은 바로 판매 화면에 반영되므로 "즉시 반영" 표시를 붙입니다. 파일 제거·서브상품 끄기·가격 변경 때는 확인 창을 띄웁니다. 마지막 파일을 지우려 하면 "숨김으로 바꾼 뒤 교체하세요"라고 안내합니다(B-02).

### 4-3. 실수 막기(가장 먼저 할 일)

구매할 수 없는 상품이 공개되는 길이 3개 있습니다.
1. 가격 0크레딧 서브상품의 공개(B-01)
2. 공개 중 상품에서 파일을 확인 없이 즉시 삭제(B-02)
3. 임시저장 상품을 "선택 숨김"한 뒤 "다시 공개"(C-01)

지금 공개 전 점검은 화면 버튼만 막을 뿐이고, 서버에는 검사가 없습니다.
- **해결:** 서버에 "공개 검사 공통 규칙" 하나를 둡니다. 규칙은 결제가 판단하는 기준과 똑같이 맞춥니다. 사용 중인 서브상품 1개 이상, 서브상품마다 파일 있음, 가격 1 이상, 전체구매를 켰다면 그 가격도 1 이상입니다.
- 결제 쪽은 이미 이런 상품의 구매를 막고 있습니다. 그래서 돈이 잘못 빠져나가지는 않고, 피해는 "살 수 없는 상품이 보이는 것"입니다(C-01 사실 확인 반영).

### 4-4. 여러 상품 한 번에 올리기(1차 마지막, 선택)
- **1단계(M):** 파일 여러 개를 한꺼번에 놓으면 이름이 같은 파일끼리 한 상품으로 묶습니다("X.pdf" + "X.hwp" → 상품 X). 미리보기 표에서 제목·카테고리·가격을 고친 뒤 [N개 임시저장으로 만들기]를 누릅니다. 결과 표에서 점검을 통과한 것만 골라 [선택 공개]합니다. 지금 있는 등록 기능을 순서대로 부르므로 권한과 기록 경로는 같습니다.
- **2단계(L, 보류 제안):** 엑셀 목록과 파일 묶음을 함께 올리는 방식입니다.
- **주의:** 로컬 개발 서버도 운영 DB를 쓰므로, 시험만 해도 실제 상품과 파일이 생깁니다. 시험용 카테고리에서 소량으로 확인합니다. 중단된 임시 상품을 정리하는 버튼도 함께 둡니다.
