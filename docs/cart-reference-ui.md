# 솔북 장바구니 참고 조사

- 조사일: 2026-09-28, 비로그인 신규 브라우저 세션
- 상세: https://solvook.com/products/3482476214105408716
- 장바구니: https://solvook.com/shop/cart
- 이 문서는 관찰과 제안을 분리한다. 솔북 계정 생성, 로그인, 장바구니 추가/삭제 API, 주문 생성, 실제 결제는 수행하지 않았다.

## 직접 확인한 UI

1. PC 1440px에서는 표지·샘플 버튼, 상품 설명, 오른쪽 구매 옵션 패널이 나뉜다. 패널에는 구매 방식 선택, 옵션, 합계/상품 수, 쿠폰 진입점, 보라색 장바구니 버튼이 있다.
2. 해당 상품에는 열람·출력과 PDF 소장이라는 서로 다른 판매 옵션이 있다. 사이트의 대여/쿠폰/현금 가격 정책을 이 프로젝트에 그대로 도입하는 요구로 해석하지 않는다.
3. 장바구니 버튼은 측정 당시 높이 48px, 모서리 6px, 보라색 채움이었다. 프로젝트에서는 원시 색상·너비 값을 복사하지 않고 DESIGN.md의 Studio token과 Button을 사용한다.
4. 모바일 390px에서는 표지→상품 정보가 세로로 배치되고 하단에 가격과 구매 진입 버튼이 고정된다. 이 버튼을 누르면 옵션 선택 및 장바구니 버튼을 담은 바텀시트가 열린다. 이 단계는 주문 생성이 아닌 선택 UI임을 클라이언트 코드와 실제 동작으로 확인했다.
5. `/shop/cart` 최초 렌더에는 자료·제본·배송 상품 탭과 빈 상태, 홈 이동 버튼이 보였고, 인증 초기화 후 `/member/login?redirectPath=%2Fshop%2Fcart`로 이동했다. 따라서 비로그인 장바구니가 영구 지원된다고 해석하면 안 된다.
6. 상품의 옵션 선택 표시와 합계가 관찰 시점에 일치하지 않는 경우가 있었다. 이를 정상 가격 규칙으로 채택하지 않는다. 본 프로젝트의 합계는 서버 견적과 최종 DB 재계산으로 검증한다.

## 공개 클라이언트 코드에서 확인한 구조 — 인증 후 화면 실측 아님

- 확인한 페이지 번들: `/_next/static/chunks/pages/shop/cart-e4ecd701542fbef2.js`.
- 현재 장바구니 조회와 행 추가/삭제용 API 경로가 분리되어 있다.
- 빈 상태, 삭제 확인, 판매 중지 상품 안내, 상품 금액/결제 금액 요약, 장바구니로부터 주문 생성하는 별도 단계가 구현되어 있다.
- PC 목록·금액 패널의 가로 배치와 작은 화면의 세로 전환 코드가 있다.
- **선택 구매, 전체 선택, 할인 적용 결과, 담긴 장바구니의 실제 반응형 화면, 중복 소유 정책은 로그인 후 실측하지 않았다.** 아래 UX는 프로젝트를 위한 설계이며 솔북 관찰 사실이라고 주장하지 않는다.

## 이 프로젝트에 적용할 UX

- 실제 판매 단위인 서브상품·번들·레거시 PDF/HWP/ZIP을 명확히 고른 뒤 담는다. 디지털 상품 수량은 1개이며 반복 담기는 같은 항목을 반환한다.
- `/cart`에서 과목별 그룹, 선택/전체 선택, 선택 삭제, 샘플, 현재 가격, 보유/판매 중지/가격 변경 안내를 제공한다.
- PC는 목록과 선택 금액 요약, 모바일은 한 열과 하단 고정 요약을 사용한다. 상세의 왼쪽 카테고리 메뉴와 충돌하지 않도록 구매 UI를 기존 본문/옵션 영역에 둔다.
- 서버에 로그인 계정별로 보관하고, 비로그인은 로그인 후 원래 상품 옵션으로 복귀한다. 로그인만으로 자동 구매하지 않는다.
- 선택 항목은 기존 크레딧으로 일괄 구매한다. 부족하면 기존 충전 페이지를 거쳐 돌아와 새 견적을 확인한다. 자료 구매를 현금 결제 API에 바로 연결하지 않는다.
- 로그인 뒤의 실측을 요구하지 않는 범위에서, 이 프로젝트의 접근성·모바일·권한·가격 정책을 기준으로 구현 계획을 검증한다.

## 증거의 한계

검색 엔진의 상세 페이지 사본은 이전 가격·이전 문구를 포함하므로 현재 브라우저 관찰을 우선했다. 인증 뒤의 채워진 장바구니를 재현한 것처럼 설명하지 않으며, 로그인 우회나 실제 외부 주문 생성으로 검증하지 않았다.
