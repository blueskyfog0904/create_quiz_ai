# 미뤄 둔 항목 점검표

2026-11-17 기준. 관리자 운영 개선(`docs/admin-operations-improvement-plan.md`)을 진행하면서 "나중에 해도 되는 것"으로 넘긴 항목을 한곳에 모았다.
지금 당장 막힌 것은 없고, 각 항목은 확인·결정·작업이 끝나면 체크한다.

## 1. 대표님이 직접 하실 설정

- [ ] **슬랙 웹훅 등록**: Supabase 대시보드 › Vault에 `admin_alert_slack_webhook_url` 이름으로 등록. 등록 전까지 대시보드에 "슬랙 알림 미설정"으로 나오고, 관리자 알림은 화면(종·토스트)으로만 온다.
- [ ] **Resend 메일 수신 확인**: 실제 메일이 도착하는지 한 번 확인. 확인돼야 비밀번호 재설정(W3-7)과 메일 알림(U1-6)을 진행할 수 있다.
- [ ] **외부 가동 감시(W0-9)**: 사이트가 죽었을 때 알려 주는 외부 감시 서비스 연결(하트비트 주소는 Vault `admin_alert_heartbeat_url`).
- [ ] **`test` 요금제 끄기**: 1,000원 테스트 요금제. 테스트가 끝나면 요금제 관리에서 직접 끈다.
- [ ] **삼성 브라우저 밝은 화면 확인**: 다크 모드 기기에서 화면이 어둡게 뒤집히지 않는지.
- [ ] **admin01~03 권한 낮추기**: 지금 관리자 4명이 모두 대표(owner)다. 실제 CS 계정을 만들기 전에 정리한다(권한 부여 화면 U3-4 뒤).

## 2. 대표님이 직접 해 볼 쓰기 테스트

회원 계정과 관리자 계정을 번갈아 쓰는 테스트라 대표님이 하기로 했다. 결과가 이상하면 알려 주면 된다.

- [ ] **문의 답변 뒤 숫자 변화**: 대기 중 문의에 답하면 문의 관리의 대기 −1·해결 +1, 종 배지 감소, 회원에게 알림·답변 표시.
- [ ] **회원이 삭제한 문의**: 회원이 문의를 지우면 관리자 화면 "고객 삭제" +1, 열면 읽기만 되고 답변 칸이 없음.
- [ ] **환불 심사 중 다운로드 차단**: 구매 → (다운로드하지 않고) 환불 요청 → 관리자가 승인하기 전 상태에서 회원의 보관함과 상품 상세에 "환불 심사 중"이 뜨고 다운로드가 막히는지. 지금까지는 요청 직후 바로 승인돼 이 상태를 본 적이 없다.
- [ ] **환불 거부 알림**: 마켓 환불을 거부했을 때 회원에게 가는 알림과 연결 화면.
- [x] **충전 완료 뒤 머리말 잔액** (2026-11-17 대표님 확인): 실제 충전 결제 뒤 결과 화면에서 머리말의 보유 크레딧이 새 값으로 바뀌는지.
- [ ] **문의 관리 2쪽 이동**: 문의가 20건을 넘으면 쪽 이동이 되는지(지금은 7건이라 확인 불가).
- [ ] **카테고리 관리 탭**: 추가·수정·숨김이 전과 같이 되는지.

## 3. 결정이 필요한 것

- [ ] **묶음 상품 가격 정책**: 구성 일부를 이미 산 회원이 전체 묶음을 살 때 전액을 받을지. 클라이언트 확인 뒤 결정하기로 함.
- [ ] **환불 요청과 문의의 관계**: 지금은 환불 요청이 문의를 자동으로 만들지 않는다. 문의 카테고리에 "환불 요청"이 있어 회원이 문의로 환불을 요청할 수 있는데, 그러면 환불 관리에는 아무것도 올라오지 않는다. (권장) 문의 작성 화면에서 환불 카테고리를 고르면 환불 버튼으로 안내 / (대안) 환불 요청 시 문의도 자동 생성.
- [ ] **옛 관리자 알림 11건 삭제 여부**: 관리자 계정의 회원용 알림함에 남은 옛 관리자용 알림.
- [ ] **0크레딧 환불 승인 문구**: 환불 크레딧이 0일 때 회원 알림 문구.
- [ ] **환불 거부 알림의 연결 화면**: `/mypage/support`와 `/library` 중 어디로 보낼지.
- [ ] **"환불액 미정" 문구**: 환불이 끝났는데 금액 기록이 없는 옛 테스트 환불(2월 3건)에 "환불액 미정"으로 나온다. "금액 기록 없음" 같은 문구로 바꿀지.
- [ ] **결제 화면의 문의 메일 주소**: `/checkout` 아래에 "결제 문의: support@createquizai.com"으로 나온다. 사이트 주소(summersuninst.com)와 다른 도메인인데 실제로 받는 주소가 맞는지.
- [ ] **테스트 데이터 정리**: 테스트 문의 7건, 마켓 주문 2건·환불 요청 1건, `archive.deleted_test_market_rows_20261113` 보관 표를 출시 전에 지울지.

## 4. 나중에 해도 되는 코드 정리

동작에는 문제가 없고, 손볼 때 함께 정리하면 되는 것들이다.

### 화면

- [ ] 문의 상태 이름표가 세 화면(문의 관리, 회원 상세, 대시보드)에 각각 들어 있음 → 하나로 합치기.
- [ ] 문의 상세의 "다른 문의 N건" 링크가 이메일 검색 목록으로 가서 지금 보던 문의도 포함됨(숫자가 1 많게 보임). 비슷한 이메일의 다른 회원이 섞일 수 있음.
- [ ] 문의 관리에서 필터를 적용하거나 쪽을 옮기면 "카테고리 관리" 탭이 "문의 목록"으로 돌아옴.
- [ ] `?ticket=` 링크로 연 문의 창을 닫아도 주소에 남아 새로고침하면 다시 열림.
- [ ] 회원 상세의 크레딧 거래 표 "유형" 칸이 모바일에서 두 줄로 꺾임.
- [ ] 회원 상세로 가는 링크가 후기 관리, 수동 확인 주문 목록에는 아직 없음.
- [ ] 회원 상세·대시보드의 회원 이름 링크가 `members.view` 권한이 없는 계정에도 보임(누르면 권한 없음 화면). 권한 적용(U3-3) 때 정리.
- [ ] 대시보드 로딩 뼈대가 옛 배치(3칸) 그대로.
- [ ] 대시보드 결제 합계는 결제 직후 취소 대기·수동 확인 상태인 주문을 그동안 빼고 센다. 화면 설명에는 이 내용이 없음.
- [ ] 회원 상세 "이메일로 검색" 링크는 부분 일치라 비슷한 이메일의 다른 회원이 함께 나올 수 있음.
- [ ] 옛(v1) 다운로드 버튼도 새(v2) 환불 심사 중 상태에 막힘.

### 서버·DB

- [ ] `support_tickets.is_deleted_by_user`가 빈 값을 허용함. 지금은 빈 값 0건이지만 생기면 그 문의는 목록·답변에서 빠진다 → NOT NULL로(DB 작업).
- [ ] 이미 답변한 문의에 서버가 답변을 다시 저장할 수 있음(화면에는 버튼이 없음).
- [ ] 문의 검색의 회원 수 상한(50) 상수가 주문 조회의 상수와 중복.
- [ ] 권한이 읽히지 않으면 대시보드의 지표·최근 목록이 "권한 없음"처럼 조용히 빠짐(가입 수·처리 대기는 보임). "불러오지 못했습니다"로 구분할지.
- [ ] 조회 상한: 권한·파일 조회 1,000행, 다운로드 기록 500행. 데이터가 늘면 나눠 읽기로 바꿔야 함.
- [ ] 권한 가드에 "관리자면 누구나", "두 권한 중 하나" 형태가 없음.
- [ ] `profiles` 표에 anon·authenticated의 DELETE·TRUNCATE·INSERT 표 권한이 남아 있음 → DB-P2/P3에서 정리.
- [ ] 대표 두 명이 동시에 서로를 지우는 경우의 방어(DB-P2).
- [ ] DB-P3 메모: 새 함수를 쓰는 정책에 `TO authenticated`, `products.delete`는 두 권한이 모두 필요, `'owner'` 권한 값 처리.
- [ ] `payapp-webhook-server.ts`의 `notifyAdmins` 필드가 이제 읽히지 않음.
- [ ] 계획 문서 116·159행이 아직 "owner = 대표 한 명"으로 적혀 있음.
- [ ] 확장자로 끝나는 동적 주소에서 `x-auth-user-id` 헤더가 걸러지지 않는 문제(`src/lib/request-auth.ts`).
