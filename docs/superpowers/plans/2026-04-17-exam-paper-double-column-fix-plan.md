# 문제지 PDF 2단 레이아웃 심화 개선 계획

> **에이전트 작업 지침:** 이 계획은 체크박스(`- [ ]`) 단위로 실행합니다. 각 단계는 **분석 → 계획 → 구현 → 검증** loop를 따르며, 검증을 통과하기 전에는 다음 단계로 진행하지 않습니다.

**목표:** 문제지 PDF 저장 워크스페이스에서 `시험지+답안 + 2단` 조합일 때, 페이지/컬럼 경계에서 문제 본문이 사라지고 정답·해설만 다음 위치에 남는 현상을 해결한다. 사용자가 실제로 읽고 풀 수 있는 **문제 본문 단위**가 항상 유지되도록 PDF 생성 구조를 개선한다.

**아키텍처:** 현재 구현은 2단 모드에서 문제를 좌/우 컬럼 스택으로 분할하지만, 각 문제를 하나의 `stack` 블록으로 다루고 있으며 `시험지+답안`에서는 문제 본문과 정답/해설이 같은 문제 블록에 포함된다. 이 상태에서 컬럼/페이지 경계에 걸리면 pdfmake가 블록을 의도치 않게 분할하거나 밀어내면서, 본문이 사라지고 정답·해설만 보이는 현상이 생길 수 있다. 따라서 개선의 핵심은 **문제 블록을 “본문 단위”와 “정답/해설 단위”로 분리**하고, 2단 모드에서는 최소 본문 단위를 우선 보존하는 방향으로 레이아웃 전략을 다시 설계하는 것이다.

**기술 스택:** Next.js App Router, TypeScript, pdfMake, 브라우저 내장 PDF viewer(iframe/new tab), Node test runner, ESLint

---

## 심화 구조 원인 분석

### 원인 1 — `columns` 안에 좌/우 전체 stack을 통째로 넣는 구조
현재 2단은 진짜 문서 흐름형 2단이 아니라, `leftColumn/rightColumn` 전체를 각각 하나의 큰 `stack`으로 `columns`에 넣는 구조다.
이 때문에 pdfmake는 컬럼 전체를 큰 블록처럼 다루게 되고, 특정 문제가 페이지/컬럼 경계에 걸릴 때 자연스러운 재배치보다 거친 분할을 만들 수 있다.

### 원인 2 — 문제 1개가 본문과 정답/해설을 모두 포함한 단일 큰 stack
현재 `시험지+답안`에서는 한 문제가 다음 요소를 모두 포함한 단일 stack이다.
- 문제 번호/문제문
- 지문
- 선택지
- 정답
- 해설

2단에서 이 큰 stack이 컬럼 높이를 넘으면, 본문은 앞쪽에서 잘려 사라진 것처럼 보이고 정답/해설만 다음 위치에 남는 현상이 발생할 수 있다.

### 원인 3 — 문자열 길이 기반 weight 분배의 한계
현재 좌/우 컬럼 분배는 문자열 길이 기반 `estimateQuestionNodeWeight()`에 의존한다.
하지만 실제 렌더 높이는
- 줄바꿈 수
- boxedText margin
- 선택지 개수
- 정답/해설 길이
- 한글/영문 혼합
등의 영향을 크게 받으므로, 문자열 길이 기반 추정은 컬럼 균형과 페이지 경계 안전성을 충분히 보장하지 못한다.

## 현재 관찰된 실패 조건

현재 실패는 모든 조합이 아니라 아래 조건에서 집중적으로 발생한다.

- `시험지` + `2단` → 정상
- `답안` + `2단` → 정상
- **`시험지+답안` + `2단` → 비정상 (문제 본문 누락 / 정답·해설만 보임)**

즉, 문제는 단순히 2단 자체가 아니라:
> **본문 + 정답/해설이 한 블록에 결합된 상태로 2단 컬럼 경계에 걸릴 때** 발생하는 구조 문제

이다.

---

## 현재 구조 진단

현재 `src/lib/exam-paper-pdf.ts` 구조의 핵심:

1. 문제 하나를 하나의 `stack`으로 만든다.
2. 그 안에 아래가 순서대로 들어간다.
   - 문제 번호/문제문
   - 지문
   - 선택지
   - 정답
   - 해설
3. 2단일 때는 이 문제 블록들을 좌/우 컬럼으로 분배한다.

즉, 현재는 “문제 본문”과 “정답/해설”이 **레이아웃적으로 같은 생명주기**를 가진다.

이 구조의 문제:
- 긴 문제는 본문과 해설까지 합쳐져 블록이 커짐
- 컬럼 끝에 걸치면 pdfmake가 블록 전체를 안전하게 배치하지 못함
- 결과적으로
  - 본문 일부/전체가 앞쪽에서 사라지거나
  - 정답/해설만 다음 위치에 남는 식의 비정상 출력이 생김

---

# 핵심 가설

## 가설 A — 최소 보장 단위가 잘못 설정되어 있다
현재는 “문제 전체”를 하나로 다루거나, 반대로 2단 모드에서 너무 자유롭게 쪼개면서 본문/해설 관계가 깨진다.

하지만 실제로는 사용자가 반드시 봐야 하는 최소 단위는:

- `문제 번호 + 문제문 + 지문(있다면) + 선택지`

이다.

정답/해설은 그 다음에 따라와도 되지만,
- 본문 없이 정답/해설만 보이는 건 실패
- 선택지 없이 해설만 보이는 것도 실패

즉, **최소 보장 단위는 “문제 본문”**이고,
`정답/해설`은 후속 블록으로 분리할 수 있다.

---

## 가설 B — 현재 컬럼 분배 기준(weight 분할)이 시각적 높이와 불일치한다
현재는 문자열 길이 기반 weight로 좌/우 컬럼을 나눈다.
하지만 실제 PDF 높이에 영향을 주는 건:
- 줄바꿈 수
- 선택지 개수
- 지문 상자 유무
- 해설 길이
- 문단 스타일
이다.

따라서 단순 길이 기반 분배는 균형이 대략적일 뿐,
페이지/컬럼 경계 문제를 막아주지 못한다.

---

## 가설 C — 2단 모드에서 `시험지+답안`은 별도 렌더링 전략이 필요하다
`시험지` / `답안` 단독 모드는 단순하다.
하지만 `시험지+답안`은 한 문제에 대해:
- 본문 블록
- 정답 블록
- 해설 블록
이 모두 존재하므로,
2단일 때는 이 모드만 별도 규칙으로 처리하는 것이 자연스럽다.

즉,
- `시험지` / `답안`은 현재 경로 유지 가능
- **`시험지+답안` + `2단`만 별도 생성 전략**을 두는 게 현실적일 수 있다.

---

# 권장 개선 방향

## 방향 1 — 문제 블록을 2개로 분리 (권장)
### 문제 본문 블록
포함:
- 문제 번호
- 문제문
- 지문
- 선택지

### 정답/해설 블록
포함:
- 정답
- 해설

이렇게 분리하면:
- 본문은 함께 유지 가능
- 정답/해설은 뒤로 넘어가도 맥락 유지 가능
- “본문은 없고 정답만 나오는” 문제를 줄일 수 있음

### 추가 규칙
- 본문 블록은 2단에서도 **가능하면 keep-together**
- 정답/해설 블록은 break 허용
- 단, 본문보다 먼저 렌더되면 안 됨

---

## 방향 2 — `시험지+답안 + 2단`만 별도 PDF 생성 경로로 분리 (현실적 대안)
현재 공통 생성 함수에서 모든 모드를 같이 처리하는데,
이 조합은 구조적으로 더 복잡하므로 아래처럼 분기할 수 있다.

- `시험지` / `답안` / `1단` → 기존 경로 유지
- **`시험지+답안` + `2단` → 별도 렌더링 함수**

예:
- `buildTwoColumnExamWithAnswersDefinition(...)`

이렇게 하면 나머지 경로 회귀 위험을 줄이면서,
가장 문제되는 조합만 정밀하게 제어 가능하다.

---

## 방향 3 — 문자열 길이 기반 weight 분배 대신 “본문 우선 분배”로 변경
컬럼 분배 시 기준을 단순 길이가 아니라,

- 본문 블록 높이 추정
- 해설 블록 높이 추정
- 본문이 먼저 들어가고 해설은 뒤에 따라가도록

바꿔야 한다.

최소한의 개선으로는:
- 분배는 `본문 블록` 기준으로 하고
- 정답/해설은 같은 컬럼 뒤에 붙이되,
- 필요하면 다음 컬럼/페이지로 흘리도록 설계

# 최종 권장 결론

현재 문제는 단순 spacing 조정 문제가 아니라,
**`시험지+답안 + 2단` 조합에서 문제 블록의 최소 보장 단위가 잘못 정의된 구조 문제**다.

따라서 가장 좋은 해결책은:
1. **문제 본문 블록**과
2. **정답/해설 블록**을 분리하고,
3. `시험지+답안 + 2단`만 별도 배치 전략으로 관리하는 것

이다.

---

# 최종 성공 기준

이 계획은 아래가 모두 만족될 때 성공입니다.
1. `시험지+답안 + 2단`에서 문제 본문이 사라지지 않는다.
2. 정답/해설은 본문 뒤에만 나타난다.
3. iframe 미리보기와 다운로드 PDF가 같은 결과를 보여준다.
4. `1단`, `시험지`, `답안` 경로는 유지된다.
5. 각 loop는 검증 통과 후에만 종료된다.
