## A. 약관 문장 교체(배포 뒤 스크립트)
**환불정책 '포인트 충전 심사 필수 안내' 첫 줄**
- 지금: 충전된 포인트의 이용기간과 환불가능기간은 결제시점으로부터 1년 이내로 제한됩니다.
- 바꿈: 충전한 크레딧은 결제한 때부터 1년 동안 쓸 수 있고(만료 일시는 크레딧 화면에 표시), 기간이 지나면 남은 크레딧은 쓸 수 없습니다. 단순 변심에 따른 결제 취소(환불)는 결제일 다음 날부터 7일째 되는 날까지, 그 충전 건의 크레딧을 하나도 쓰지 않았을 때 신청할 수 있습니다. 충전한 크레딧의 이용기간과 단순 변심에 따른 환불 신청 기간은 모두 결제한 때부터 1년을 넘지 않습니다(자료 환불로 다시 받은 크레딧의 이용기간은 3-2절 ⑥, 결제 오류·표시와 다른 제공·미성년자·서비스 종료는 3절④·7절·8절).

**같은 안내 넷째 줄**
- 지금: 구매 후 7일 이내이고 해당 충전 크레딧을 전혀 사용하지 않은 경우에만 환불을 요청할 수 있습니다.
- 바꿈: 단순 변심에 따른 환불은 결제일 다음 날부터 7일째 되는 날까지, 해당 충전 크레딧을 전혀 쓰지 않았을 때 마이페이지 크레딧 화면 또는 고객센터로 요청할 수 있습니다(결제 오류·미성년자 결제·서비스 종료는 3절④·7절·8절).

**환불정책 3절①**
- 지금: 구매 후 7일 이내이고 해당 결제로 충전된 크레딧(포인트)을 1개도 사용하지 않은 경우 결제 취소 또는 환불을 요청할 수 있습니다.
- 바꿈: 결제일 다음 날부터 7일째 되는 날까지(크레딧 지급이 결제보다 늦어지면 지급일 다음 날부터), 해당 결제로 충전된 크레딧을 1개도 사용하지 않은 경우 크레딧 화면 또는 고객센터로 결제 취소(환불)를 요청할 수 있습니다.

**환불정책 2절③** → '…결제한 때부터 1년(만료 일시는 크레딧 화면에 표시)이며, 기간이 지나면 남은 크레딧은 쓸 수 없습니다.'로 문장 전체(뒤 문장 '기간이 경과한 크레딧은 사용이 제한될 수 있습니다' 포함)를 바꿈. 스크립트가 두 문장이 정확히 1번씩 있는지 확인.

**환불정책 8절(서비스 종료)에 덧붙임**
- 환불 금액은 남은 유료 크레딧 × (그 충전의 결제 금액 − 이미 환불한 금액) ÷ (지급 크레딧(보너스 포함) − 회수한 크레딧)으로 계산하며 1원 미만은 버립니다. 유효기간이 지나지 않은 크레딧만 계산하고, 자료 환불로 다시 받은 크레딧은 원래 충전분으로 계산합니다.

**환불정책 3절④ 끝에 덧붙임**: 표시·광고나 계약 내용과 다르게 제공된 경우에는 제공받은 날부터 3개월, 그 사실을 안 날(또는 알 수 있었던 날)부터 30일 안에 취소할 수 있습니다.

**환불정책 5절에 덧붙임**: 회사 사정으로 환급이 늦어지면 관련 법령에 따른 지연배상금을 지급합니다.

**이용약관 '크레딧(충전형 포인트) 이용조건' 첫 문장**
- 바꿈: 충전한 크레딧의 이용기간은 결제한 때부터 1년이며, 단순 변심에 따른 결제 취소(환불)는 결제일 다음 날부터 7일째 되는 날까지 그 충전 건을 쓰지 않았을 때 신청할 수 있습니다.

**이용약관 13조(서비스 종료)에 덧붙임**: 환불 금액 계산은 취소·환불정책 8절에 따릅니다.

(절 이름 '포인트 충전 심사 필수 안내'는 7절이 이름으로 가리키므로 그대로 둔다.)

## B. 결제(충전) 화면 — 동의 체크 바로 위에 둔다
**제목**: 결제 전 확인
1. (product) 자동결제 없이 한 번만 결제되는 충전 상품이며, 1회 최대 100,000원까지 충전할 수 있습니다. 결제 금액과 받는 크레딧(보너스 포함)은 주문 내용과 같고, 크레딧은 결제가 끝나면 바로 지급됩니다.
2. (validity) 충전한 크레딧은 결제한 때부터 1년 동안 쓸 수 있고(만료 일시는 크레딧 화면에 표시), 기간이 지나면 남은 크레딧은 쓸 수 없습니다. 다른 회원에게 넘길 수 없습니다.
3. (refund) 결제일 다음 날부터 {충전환불기간}일째 되는 날까지(크레딧 지급이 결제보다 늦어지면 지급일 다음 날부터) 이 충전 건의 크레딧을 하나도 쓰지 않았다면, 크레딧 화면이나 고객센터로 신청해 결제 금액 전액을 돌려받을 수 있습니다. 신청 후 3영업일 안에 원래 결제수단의 취소를 요청합니다(휴대폰 결제는 결제한 달이 지나면 취소되지 않을 수 있어, 이때는 본인 명의 계좌로 환불합니다).
4. (restriction) 이 충전 건의 크레딧을 하나라도 쓰면 단순 변심으로 취소할 수 없습니다. 크레딧은 유효기간이 먼저 끝나는 것부터 쓰입니다.
5. (otherCases) 결제 오류·중복 결제·주문 내용과 다르게 제공된 경우·서비스 종료는 취소·환불정책의 별도 기준을 따릅니다.

**미성년자 안내**: 미성년자가 법정대리인의 동의 없이 결제한 경우 본인이나 법정대리인이 결제를 취소할 수 있습니다(법정대리인이 쓰도록 허락한 돈이거나, 성년인 것처럼 속인 경우 등은 제외). 고객센터(1:1 문의·이메일·전화)로 알려 주세요. 취소되면 남은 크레딧은 회수하며, 자세한 기준은 취소·환불정책 7절을 따릅니다.

**동의 체크(필수)**: 주문 내용과 결제 전 확인, 취소·환불정책을 확인했으며 결제에 동의합니다. ('취소·환불정책'은 코드가 링크로 감싸고, '(필수)'는 코드가 한 번만 붙인다.)

## C. 크레딧 화면
**구매 내역 안내**: 구매건마다 남은 크레딧과 환불 가능 여부를 볼 수 있습니다. 크레딧은 유효기간이 먼저 끝나는 것부터 쓰입니다.

**환불 신청 확인창**
- 결제일 다음 날부터 {충전환불기간}일째 되는 날까지, 이 충전 건을 하나도 쓰지 않았을 때만 신청할 수 있습니다.
- 신청 뒤 담당자가 확인하며, 확인하는 동안 이 충전 건의 크레딧은 쓸 수 없습니다.
- 신청 후 3영업일 안에 원래 결제수단으로 결제 금액 전액의 취소를 요청합니다(휴대폰 결제는 결제한 달이 지나면 본인 명의 계좌로 환불, 카드사 반영은 며칠 걸릴 수 있음).

**신청 접수 안내**: 환불 신청이 접수되었습니다. 신청일부터 3영업일 안에 원래 결제수단의 취소를 요청합니다(휴대폰 결제는 결제한 달이 지나면 본인 명의 계좌로 환불).

(기산일 단서: 크레딧 지급이 결제일보다 늦어진 결제는 지급일을 결제일로 보아 판정한다 — 회원에게 유리한 쪽이라 문구는 '결제일'로 둔다.)

**환불할 수 없는 사유(회원에게 보이는 것)**
- 구매건 없음: 구매건을 찾을 수 없습니다.
- 결제 충전 건 아님: 결제로 충전한 크레딧만 환불할 수 있습니다.
- 재지급 크레딧: 자료 환불로 다시 받은 크레딧은 단순 변심 결제 취소 대상이 아닙니다(미성년자 결제 취소·서비스 종료는 취소·환불정책 7·8절).
- 결제 확인 안 됨: 원래 결제를 확인할 수 없어 환불을 신청할 수 없습니다.
- 처리 중·완료: 이미 환불 처리 중이거나 끝난 구매건입니다.
- 사용함: 이 충전 건의 크레딧을 이미 써서 환불할 수 없습니다.
- 만료: 이용기간이 끝난 크레딧은 환불할 수 없습니다.
- 기간 지남: 환불 신청 기간(결제일 다음 날부터 {충전환불기간}일)이 지났습니다.
- 확인 불가: 지금은 환불 가능 여부를 확인할 수 없습니다. 잠시 후 다시 시도하거나 고객센터로 알려 주세요(알린 시각을 신청 시각으로 봅니다).

## D. 충전 화면(/pricing) 문구 — pricing_page_content 와 코드 기본값
자리표시는 지금 이름 그대로({사용기한}{환불기간}{충전한도}{최대보너스}), {환불기간} 값은 DB refundDays.
- notice_items[0].body: 결제한 때부터 {사용기한}년 동안 쓸 수 있습니다(만료 일시는 크레딧 화면에 표시).
- notice_items[1].body: 결제일 다음 날부터 {환불기간}일째 되는 날까지 1개도 쓰지 않았다면 환불을 요청할 수 있습니다(원 결제수단으로 취소, 휴대폰 결제는 결제한 달이 지나면 본인 명의 계좌로 환불).
- refund_items[1]: 구매한 크레딧은 결제한 때부터 {사용기한}년 동안 쓸 수 있으며, 환불은 결제일 다음 날부터 {환불기간}일째 되는 날까지 크레딧을 1개도 쓰지 않은 경우 가능합니다.
- refund_items 3번째(지금 '문제마켓 자료의 다운로드/열람이 완료된 사용분은 환불이 제한됩니다.'): 문제마켓 자료 환불은 자료를 받지 않았을 때 구매일 다음 날부터 30일째 되는 날까지 신청할 수 있으며, 환불되면 결제에 쓴 크레딧으로 돌아옵니다(자세한 기준은 취소·환불정책).
- refund_items[5]: 승인된 환불은 결제 당시 쓴 원 결제수단으로 취소합니다(휴대폰 결제는 결제한 달이 지나면 본인 명의 계좌로 환불). 카드·간편결제는 결제사 기준 영업일 2~5일이 걸릴 수 있습니다.
- summary_note: 지금 문장의 '구매 후 {환불기간}일 안에'를 '결제일 다음 날부터 {환불기간}일째 되는 날까지'로, '사용 기한 {사용기한}년'을 '결제한 때부터 {사용기한}년'으로(나머지 그대로).

## E. 8번 환불정책 ⑥ 수정문 (8번 초안 B-3 ⑥을 이것으로 바꿔 저장)
⑥ 환불은 결제에 쓴 크레딧으로 돌려드립니다. 그 크레딧의 유효기간이 이미 지났거나 남은 기간이 짧으면, 구매할 때 남아 있던 기간만큼 쓸 수 있는 크레딧으로 다시 지급합니다. 이렇게 다시 받은 크레딧은 3절 ⑥의 무상 크레딧이 아니며 원래 충전 크레딧과 같게 봅니다(미성년자 결제 취소·서비스 종료 때 유료 크레딧으로 계산). 회사는 이 크레딧을 임의로 회수하지 않습니다. 다만 원래 충전 결제가 취소·환불되면, 확인하는 동안 그 결제에서 비롯해 다시 받은 크레딧은 사용이 보류되고, 취소·환불된 금액만큼 그 결제에서 비롯해 다시 받은 크레딧도 원래 충전 크레딧과 함께 회수하며(전액 취소면 남은 것 전부), 이미 쓴 몫은 담당자가 내역을 확인해 회원에게 알리고 정산합니다(미성년자 결제 취소는 7절에 따릅니다). 원래 충전 크레딧으로 되돌린 몫은 사용하지 않은 크레딧으로 보며, 그 현금 환불은 2절·3절에 따릅니다. 결제에 쓴 충전 크레딧에 현금 환불 이력이 있으면 담당자가 내역을 확인해 개별로 정산합니다.

## F. 처리 절차서(런북) — 구현 때 `docs/runbooks/` 에 작성
0. 사용 보류 수단(공통): PG 로 취소할 수 있으면 '접수 즉시 페이앱 콘솔 전취소'가 보류다(취소 통보 → 격리가 원래 원천과 다시 지급한 크레딧을 묶음). 접수부터 격리까지 사이에 쓴 몫은 수동 완료 화면의 원천별 원자료(소비 총량 = credit_consumption, 자료 환불 복구·재지급으로 넘긴 양 = allocated_items·재지급 연결, 순사용)로 대표가 판단(런북 3 근거와 같음). PG 로 취소할 수 없으면 대표 승인 뒤 리허설한 SQL 템플릿을 SQL 편집기(postgres)에서 쓴다: 보류(저장소 파일 `supabase/scripts/bundle9_point_charge_hold.sql`, 한 트랜잭션: 그 원천에 열린 요청이 이미 manual_review 면 멈추고 '이미 격리됨 — 수동 완료로' 안내, processing 이면 멈춤, 그 밖의 열린 요청(pending_review·retryable_failed)이면 새로 만들지 않고 그 요청을 manual_review·origin='external_cancel'·last_error_code='MANUAL_TEMPLATE_HOLD' 로 바꿈 — 바꾸기 전 origin·status 와 취소·부분취소 표식 값을 record_admin_audit details 에 남김, 없으면 같은 값으로 요청 생성 — 관리자 거절이 막혀 자손이 묶인 채 남는 일이 없음 → 원래 원천 → 주문 → profiles 잠금 → 자손 중 active 를 id 순으로 잠가 pending_refund → 같은 요청에 held_reissued_source_ids 기록 → record_admin_audit('point_charge_source_hold')) / 해제(`…_release.sql`; 먼저 확인: 요청이 manual_review·MANUAL_TEMPLATE_HOLD, 주문이 refunded 아님, 취소·부분취소 통보 표식이 보류 감사 details 의 값과 같음; 보류 전 요청이 회원이 낸 신청(origin user)이었으면 해제하지 말고 회원에게 연락한 뒤 수동 완료로 — 하나라도 어긋나면 멈추고 수동 완료로 보냄; 그 요청을 rejected 로 닫고 원래 원천과 held_reissued_source_ids 중 pending_refund 인 것만 active 로, record_admin_audit('point_charge_source_release')). 앞선 부분취소 표식이 있는 결제는 수동 완료를 부분 모드로 하고 쓸 수 있는 몫 합 전체를 입력.
1. 미성년자 결제 취소: 접수(본인·법정대리인 확인) → 페이앱 콘솔 취소 → 취소 통보로 격리(다시 지급한 크레딧도 함께 보류)된 건 수동 완료 → 회원 안내. PG 로 취소할 수 없으면: 보류 템플릿(요청 생성 포함) → 돌려줄 금액 계산·근거 기록(받은 이익 범위는 변호사 확인 전까지 대표 건별 판단) → 계좌 송금 → 수동 완료(bank_transfer, 전액 모드, 실제 송금액) → 계좌 정보 파기.
2. 서비스 종료: 종료 공지(기간) → 남은 유료 크레딧 계산(유효기간 안의 원천만, 다시 지급한 크레딧은 원래 충전분으로) → 환산(A의 8절 식; 이미 환불한 금액 = 완료된 refund_requests 의 refund_amount 합만, 회수한 크레딧 = payment_admin_actions.recovered_credits 합 — 계획 2-4 정의) → 원 결제수단 또는 계좌 환불.
3. 재지급 크레딧 취소 경보(REISSUED_CREDIT_HELD / REISSUED_CREDIT_SETTLE_REVIEW / REISSUED_CREDIT_HOLD_FAILED): 경보 확인 → 수동 완료 화면에서 원천별 원자료·앞선 수동 완료 기록 확인(부분취소 회수량은 8절 식과 같은 기준으로 대표가 정함) → 실제로 쓴 몫 확인(근거: 원천별 사용 = credit_consumption, 자료 환불 복구 = market_refund_requests.allocated_items·재지급 연결, 앞선 회수·만료 정리 = payment_admin_actions.details — 앞선 회수·만료 정리는 쓴 몫이 아님) → 회원 연락 → 대표 정산 기록.
4. 고객센터로 접수된 충전 철회(마지막 날이 토·일·공휴일이고 다음 평일에 온 신청 포함 — 변호사 확인 전까지 기간 안으로 봄): 접수 시각 증빙(문의 작성·메일 수신·통화 시각) → 그 시각 기준 기간·미사용 확인 → 바로 페이앱 콘솔 전취소(취소 통보 → 격리 → 격리 결과로 접수 뒤 사용 여부 확인 → 수동 완료 전액) → 회원 안내(3영업일). 설정 장애 중 신청 시도는 경보(POINT_CHARGE_POLICY_UNAVAILABLE, 시도 시각 포함)의 시각을 신청 시각으로 본다. 휴대폰 결제 당월 경과(PG 취소 불가): 보류 템플릿(요청 생성 포함) → 계좌 받기 → 계좌 정보를 받은 날부터 3영업일 안에 송금(늦으면 지연배상 계산) → 수동 완료(bank_transfer) → 계좌 정보 파기.
