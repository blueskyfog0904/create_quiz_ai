# Solvook 컨셉 국어 문제마켓 동등 적용 계획

## 0. 문서 상태

- 작성일: 2026-07-29
- 공개 대상: `/preview/solvook-concept?subject=korean`
- 영어 비교 대상: `/preview/solvook-concept?subject=english`
- 관리자 대상:
  - `/admin/market-main-settings?subject=korean`
  - `/admin/main-ad-settings?subject=korean`
- 상태: 기능 구현·검증 완료, 국어 운영 콘텐츠 입력 대기
- 목표: 현재 영어 문제마켓 메인과 같은 화면 구성·동작·관리 기능을 국어에도 적용하되, 영어와 국어의 콘텐츠와 설정은 완전히 분리한다.

이 계획은 `요청 파악 → 현재 구조·운영 데이터 확인 → 계획 작성 → 독립 검증` 순서로 작성한다. 구현 시에는 각 Phase마다 `계획 확인 → 실패 테스트 또는 재현 → 최소 구현 → 검증 → 실패 시 원인 분석과 재구현` loop를 수행하고, 검증을 통과해야 다음 Phase로 진행한다.

## 1. 요청 해석과 범위

이번 요청의 “국어도 똑같이 구현”은 다음 의미로 해석한다.

1. 상단 `영어 / 국어`에서 국어를 선택하면 같은 Solvook 컨셉 레이아웃 안에서 국어 데이터만 표시한다.
2. 본문 순서는 현재 확정된 영어 화면과 동일하게 유지한다.
   - 광고 수와 관계없이 동일한 `MainAdCarousel` 골격
   - 인기 다운로드 자료
   - 최근 등록된 수업 자료
   - 교재와 출처로 골라보기
   - 하단 문제마켓 CTA
3. `(임시)메인광고설정`과 `(임시) 문제마켓 메인 관리`에서 영어·국어를 전환해 각 과목을 따로 관리한다.
4. 영어 설정이나 콘텐츠를 국어에 복사하지 않는다. 국어 광고·출처·노출 설정은 국어 관리 화면에서 별도로 입력한다.
5. 이전 요청에서 삭제한 두 개의 빠른 진입 버튼과 별도 대형 카테고리 카드 섹션은 다시 만들지 않는다.

여기서 “카테고리 국어”는 상단 과목 카테고리인 `국어` 탭을 뜻하는 것으로 확정해 진행한다. 만약 별도의 “문제마켓 카테고리” 본문 섹션을 다시 추가하려는 의미라면 현재 확정 화면과 충돌하므로 별도 변경으로 다룬다.

## 2. 현재 구조와 운영 데이터 확인 결과

### 2.1 이미 구현된 공통 기반

| 영역 | 현재 상태 | 계획상 처리 |
|---|---|---|
| 공개 과목 전환 | `?subject=english|korean`을 읽어 같은 페이지와 컴포넌트를 사용 | 그대로 재사용 |
| 헤더 | 영어·국어 active 상태, 검색 action, 링크가 과목별로 변경 | 회귀 테스트 보강 |
| 메인 데이터 | `getMarketHomeData(subject)`가 상품·메뉴·출처·최근 자료를 과목별 조회 | 그대로 재사용 |
| 메인 광고 | `getPublicMainAdCarouselItems(subject)`가 과목별 광고 배열 조회 | 국어 실제 설정 및 대칭 검증 |
| 광고 저장 | `main_ad_carousel` v2의 `items.english`, `items.korean` 분리 | 그대로 재사용 |
| 메인 편성 저장 | `workspace_settings`의 `workspace_subject + market_home` 조합으로 분리 | 그대로 재사용 |
| 관리자 전환 | 두 관리자 화면 모두 영어·국어 전환 UI 보유 | 국어 CRUD 전체 검증 |
| 출처 | 기존 `source_type`, `source_1`~`source_4`, `source_configs` 사용 | 새 taxonomy를 만들지 않음 |

따라서 국어 전용 페이지, 국어 전용 캐러셀, 국어 전용 관리자 화면 또는 새 DB 테이블을 복제하지 않는다. 같은 컴포넌트에 명시적인 `subject`를 전달하고 저장·조회 경계에서 과목 격리를 검증하는 것이 최소 구현이다.

다만 광고 저장은 현재 전체 v2 JSON을 읽은 뒤 선택 과목을 교체하고 전체 row를 다시 쓰는 구조다. 한 요청 안에서는 반대 과목을 보존하지만, 영어와 국어 관리자가 동시에 저장하면 둘 다 이전 row를 읽고 마지막 요청이 상대 과목의 새 변경을 되돌릴 수 있다. 이 계획에서는 새 테이블을 만들지 않고, 기존 JSON의 선택 과목 slice만 row lock 안에서 원자적으로 갱신하는 DB RPC를 추가해 이 경쟁 조건을 제거한다.

### 2.2 현재 운영 데이터 차이

읽기 전용 확인 결과는 다음과 같다.

| 항목 | 영어 | 국어 |
|---|---:|---:|
| 공개 중인 메인 광고 | 3건 | 0건 |
| 노출 중인 광고 시간 | 각 5초 | 해당 없음 |
| 보이는 문제마켓 메뉴 | 2건 | 2건 |
| 공개 문제마켓 상품 | 1건 | 144건 |
| 출처 설정 | 4건 | 0건 |
| 메인 전용 설정 | 없음, 기본값 사용 | 없음, 기본값 사용 |

국어 화면이 영어와 다르게 보이는 현재 원인은 주로 다음 세 가지다.

- 국어 광고가 0건이므로 현재는 기존 보라색 hero가 표시되지만, `docs/solvook-subject-ad-shell-parity-plan.md`가 이 fallback 계약을 대체해 공통 캐러셀 골격의 빈 상태로 전환한다.
- 국어 `source_configs`가 0건이므로 “교재와 출처로 골라보기”가 준비 상태로 표시된다.
- 국어 다운로드 집계 결과가 0건이므로 인기 다운로드 섹션이 빈 상태로 표시된다.

이는 과목 전환 기능의 오류가 아니라 국어 운영 데이터의 현재 상태다. 구현에서 샘플 데이터나 영어 데이터로 가짜 채움을 하지 않는다.

## 3. 구현 계약

### 3.1 공개 국어 페이지

- `/preview/solvook-concept?subject=korean`은 영어와 같은 DOM 구조·간격·반응형·접근성 규칙을 사용한다.
- 국어 선택 시 header의 `국어`만 `aria-current`와 active underline을 가진다.
- 검색, 상품 상세, 출처 필터, CTA 링크는 모두 `/korean/market/...`로 이동한다.
- 본문 순서는 `인기 다운로드 → 최근 등록 → 교재와 출처 → CTA`로 고정한다.
- 국어 광고가 1건 이상이면 영어와 같은 `MainAdCarousel`을 사용한다.
  - 제목 진행 음영
  - 광고별 기본 5초 및 관리자 설정 시간
  - 양방향 이미지 슬라이드
  - PC·모바일 이미지 전환
  - 전체 이미지 링크
  - 이전·다음, 카운터, 키보드 조작
- 국어 광고가 0건이어도 영어와 동일한 `MainAdCarousel` 외곽 골격 안에 광고 컨트롤·가짜 광고가 없는 빈 상태를 표시한다.
- 국어 인기 다운로드가 0건이거나 출처 설정이 없을 때는 영어와 같은 section shell 안에 명시적인 빈 상태를 표시한다.
- 공개·활성·미삭제이며 같은 `workspace_subject`와 보이는 메뉴에 속한 자료만 노출한다.

### 3.2 `(임시)메인광고설정`

국어 전환 후 영어와 동일하게 다음 기능을 제공한다.

- 광고 추가, 수정, 삭제
- 위·아래 순서 변경
- 공개 여부 설정
- 왼쪽 목록 제목
- 이동 링크
- 대체 텍스트
- 광고별 노출 시간 1~60초, 새 광고 기본 5초
- PC 이미지 필수 업로드와 모바일 이미지 선택 업로드
- PC `1920×720px (8:3)`, 모바일 `1200×750px (8:5)` 권장 규격 표시

저장은 선택 과목 배열만 교체한다. 국어를 저장할 때 영어 배열과 영어 이미지 참조는 변경하거나 삭제하지 않고, 반대 방향도 동일하다.

선택 과목 교체는 단일 DB transaction/RPC에서 다음 순서로 처리한다.

1. `system_settings.main_ad_carousel` row를 잠근다.
2. 잠금 시점의 최신 전체 v2 config를 읽는다.
3. 전달받은 `english` 또는 `korean` slice만 교체하고 반대 slice는 최신 값 그대로 보존한다.
4. 저장 직전·직후 전체 config를 함께 반환한다.
5. API는 RPC가 반환한 정확한 전후 이미지 참조 차이만 obsolete 대상으로 정리한다.

따라서 영어·국어 동시 저장에서도 마지막 요청이 상대 과목의 새 값을 과거 값으로 되돌리거나, 상대 요청이 막 업로드한 이미지를 오래된 파일로 오판해 삭제하지 못하게 한다.

관리자 요청에는 `subject`를 반드시 명시한다. 누락 또는 `english|korean` 외 값은 `400`으로 거부하여 잘못된 요청이 조용히 영어 설정을 덮어쓰지 못하게 한다.

### 3.3 `(임시) 문제마켓 메인 관리`

국어 전환 후 영어와 동일하게 다음 설정을 별도로 저장한다.

- 인기 다운로드 섹션 활성화, 표시 수, 집계 기간
- 최근 등록 섹션 활성화, 표시 수
- 교재·출처 섹션 활성화, 사용할 출처 유형
- 문제마켓 메뉴 선택과 순서

국어 설정은 `workspace_subject='korean'`, `setting_key='market_home'`에 저장한다. 관리자 API는 국어 메뉴 ID와 국어 출처 유형만 허용하며 영어 ID를 섞은 요청은 `400`으로 거부한다.

출처 자체의 CRUD는 이 화면에 복제하지 않는다. 기존 `/admin/source-configs?subject=korean`에서 국어 출처 이름과 `source_1`~`source_4` 옵션을 등록한 뒤, 메인 관리 화면에서 노출할 유형을 선택한다.

## 4. 데이터 온보딩 원칙

코드 구현만으로 국어 광고·출처·인기 순위를 임의 생성하지 않는다.

1. 국어 광고
   - 관리자가 국어 전환 후 제목, 이미지, 링크, 시간을 입력한다.
   - 영어 광고를 자동 복사하지 않는다.
2. 국어 출처
   - 기존 국어 상품의 `source_type`, `source_1`~`source_4` 값에 맞춰 `source_configs`를 등록한다.
   - 공란이나 불완전한 path를 임의로 추론해 분류하지 않는다.
3. 인기 다운로드
   - 국어 `market_download_events`의 실제 사용자 집계가 생긴 뒤 순위가 노출된다.
   - 데이터가 없을 때 조회수나 영어 순위를 대신 표시하지 않는다.
4. 최근 등록
   - 현재 공개된 국어 상품을 `published_at desc → created_at desc → id asc`로 표시한다.

## 6. 구현 Phase와 검증 loop

### Phase 0. 변경 소유권과 운영 데이터 백업

계획 확인:

- 현재 worktree에는 기존 문제마켓·광고 작업의 미커밋 변경이 있다.
- 구현 전에 `git status --short`, `git diff --name-status`, 기존 orchestration의 `filesModified`를 대조한다.

검증 게이트:

- 이번 계획의 허용 파일 밖 기존 변경을 수정·복원·삭제하지 않는다.
- broad `git restore`, `git checkout`, `git reset`, untracked 파일 삭제를 하지 않는다.
- 실데이터를 이용한 통합 테스트 전에 영어·국어 `main_ad_carousel` 전체 JSON과 Storage 참조 목록을 백업한다.

### Phase 1. 과목 격리 계약을 테스트로 고정

계획 확인:

- 공개 페이지, 광고 API, 메인 설정 API에서 `subject`가 단일 source of truth인지 확인한다.

구현:

- 영어·국어 대칭 테스트를 먼저 추가하고 현재 실패 여부를 확인한다.
- 광고 저장 API의 subject 누락이 영어로 fallback되는 계약은 실패 테스트로 재현한 뒤 명시적 `400`으로 수정한다.
- 국어 저장 후 영어 config가 byte-equivalent하게 유지되는지 검증한다.
- 현재 전체 JSON read-modify-write의 동시 저장 경쟁을 재현한 뒤, 선택 과목 slice 원자 갱신 RPC로 교체한다.
- RPC는 service role만 실행할 수 있게 하고 저장 전·후 전체 config를 반환한다.
- Storage obsolete 계산은 API가 미리 읽은 stale config가 아니라 RPC 반환값만 사용한다.

검증 게이트:

- `subject=english|korean`만 성공한다.
- 누락·invalid subject는 `400`이다.
- 교차 과목 메뉴 ID, 출처 유형, 광고 ID는 저장되지 않는다.
- 401, 403, 400, 성공 응답을 모두 검증한다.
- 영어와 국어 저장을 동시에 실행해도 양쪽 최신 값이 모두 남는다.
- 동시 저장 중 한 과목이 새로 올린 이미지가 상대 과목 cleanup 대상이 되지 않는다.
- RPC는 public, anon, authenticated에서 실행할 수 없고 service role 경계에서만 호출된다.

### Phase 2. 국어 관리자 기능 대칭 검증과 최소 수정

계획 확인:

- 두 관리자 화면의 영어·국어 switch, 로컬 draft 초기화, 저장 URL을 확인한다.

구현:

- 국어에서 광고 추가·수정·정렬·활성화·삭제·이미지 업로드를 검증한다.
- 국어에서 메인 섹션 활성화·limit·집계 기간·메뉴 순서·출처 유형을 저장하고 다시 불러온다.
- 테스트로 드러난 국어 전용 결함만 공통 컴포넌트에서 수정한다.

검증 게이트:

- 국어 화면에서 저장 후 재접속해 동일 값이 보인다.
- 국어 저장 전후 영어 설정과 영어 이미지 URL은 변하지 않는다.
- 국어 광고 삭제가 영어에서 참조하는 Storage object를 삭제하지 않는다.
- 버튼은 44×44px 이상, focus-visible, 키보드 조작을 만족한다.

### Phase 3. 국어 운영 데이터 온보딩

계획 확인:

- 국어 광고 원본 이미지·문구·링크와 국어 출처 분류표는 관리자 입력 데이터이며 코드 fixture가 아니다.

구현:

- 제공된 국어 광고를 `(임시)메인광고설정`의 국어 영역에 입력한다.
- 실제 국어 상품의 출처 값을 확인한 뒤 `/admin/source-configs?subject=korean`에 기존 출처 필드를 설정한다.
- `(임시) 문제마켓 메인 관리`의 국어 영역에서 section과 노출 메뉴·출처 유형을 선택한다.

검증 게이트:

- 저장된 광고·출처·메인 설정이 모두 `korean`에만 속한다.
- 공란 source path를 임의 생성하지 않는다.
- 아직 다운로드 이벤트가 없는 경우 인기 섹션의 빈 상태를 정상 결과로 인정한다.

### Phase 4. 공개 국어 페이지 브라우저 검증

계획 확인:

- 영어에서 확정된 화면 구성과 광고 동작을 국어에서도 동일한 기준으로 검증한다.

검증 게이트:

- 국어 탭, 검색, hero, 상품, 출처, CTA 링크에 영어 경로가 섞이지 않는다.
- 본문 순서가 `인기 다운로드 → 최근 등록 → 교재와 출처 → CTA`다.
- 광고 0건은 공통 캐러셀 골격의 빈 상태, 1건은 정적 광고, 복수는 자동 캐러셀이다.
- 복수 광고의 진행 음영이 실제 DOM box 기준 0%에서 100%까지 증가한다.
- 광고별 설정 시간 이후 100% 프레임을 거쳐 다음 이미지가 왼쪽으로 나가고 새 이미지가 오른쪽에서 들어온다.
- 제목, 이미지, 링크, 카운터가 같은 광고 index를 가리킨다.
- 320, 390, 640, 768, 1079, 1200, 1280px에서 가로 overflow가 없다.
- Tab, Enter, Space, 이전·다음, focus-visible과 44px target을 검증한다.
- 모바일 이미지가 없으면 PC 이미지 fallback이 동작한다.
- `prefers-reduced-motion`에서는 자동 진행을 멈추고 수동 전환은 가능하다.

### Phase 5. 통합 회귀와 독립 검증

자동 검증:

1. 관련 Node 계약 테스트
2. RPC SQL/pgTAP 또는 동등한 로컬 DB 통합 테스트
3. 변경 파일 대상 ESLint
4. `npx tsc --noEmit`
5. `git diff --check`
6. `npm run build`

운영 상태 검증:

- 테스트용 국어 광고·설정을 사용했다면 `finally`에서 원래 JSON과 Storage 상태를 복원한다.
- 복원 후 영어·국어 광고 수, 시간, 이미지 참조가 백업과 일치하는지 재조회한다.
- 신규 orphan Storage object가 없는지 확인한다.

독립 검토:

- 별도 검토자가 요구사항, 이 계획, 최종 diff와 자동·브라우저 검증 증거를 대조한다.
- `FAIL`이면 원인을 해당 Phase로 되돌려 최소 수정하고 다시 전체 검토한다.
- `PASS`가 나오기 전에는 구현 완료로 보고하지 않는다.

## 7. 완료 조건

- 국어 탭에서 영어와 동일한 화면 구성·동작이 실제 국어 데이터로 렌더된다.
- 두 관리자 화면에서 국어를 선택해 영어와 같은 기능을 사용할 수 있다.
- 영어와 국어 저장·조회·이미지 수명주기가 서로 오염되지 않는다.
- 영어와 국어 관리자가 동시에 광고를 저장해도 두 과목의 최신 변경과 이미지 참조가 모두 보존된다.
- 국어 광고·출처·인기 데이터가 없을 때 샘플이나 영어 데이터 대신 정확한 빈 상태가 보인다.
- 기존 영어 화면과 최근 수정한 광고 진행 음영·슬라이드 동작에 회귀가 없다.
- 관련 테스트, 대상 lint, TypeScript, build, 브라우저 검증, 독립 검토가 모두 통과한다.

## 8. 구현 착수 시 필요한 운영 입력

코드 및 관리자 기능 검증은 바로 진행할 수 있다. 실제 국어 화면을 광고와 출처 카드까지 채우려면 다음 운영 입력이 별도로 필요하다.

- 국어 광고별 제목, PC 이미지, 선택 모바일 이미지, 이동 링크, 대체 텍스트, 노출 시간
- 국어 상품에서 사용할 `source_type`별 `source_1`~`source_4` 라벨과 옵션
- 국어 메인에서 노출할 문제마켓 메뉴와 순서

이 값이 아직 없으면 기능 구현과 빈 상태 검증까지 완료하고, 실제 콘텐츠 입력은 관리자 온보딩 단계로 남긴다.
