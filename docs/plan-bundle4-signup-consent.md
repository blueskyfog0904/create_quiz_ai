### 공백 규칙(DB·코드 공통, 하나)
- '정리 값' = CRLF→LF 로 바꾼 뒤 **앞뒤의 모든 공백(스페이스·탭·줄바꿈·NBSP 등)** 을 지운 값. SQL 은 공용 함수 `consent_normalize_text(text)`(IMMUTABLE, DEFINER 아님, `regexp_replace(…, 'g')` 로 앞뒤 공백 제거 — 로케일에 기대지 않는 **명시적 문자 목록**(스페이스·\t·\n·\r·\v·\f·U+00A0·U+1680·U+2000–200A·U+2028·U+2029·U+202F·U+205F·U+3000·U+FEFF) 하나, TS 도 같은 목록) 하나.
- '빈 값' = 정리 값이 ''. CHECK·VERIFY·저장 비교·원본 약관 판정·서버 사전 검사가 모두 이 규칙.
- 표 테스트: '\n', '\t', NBSP, U+3000, U+FEFF, 앞뒤 동시 공백, 끝 줄바꿈만 다른 내용 → SQL·TS 결과 같음.

## 2. DB (관례: 머리말(system_settings RESTRICTIVE 정책 추가·profiles FK 생성 때 잠깐 걸리는 잠금 설명 포함), SET LOCAL lock_timeout·statement_timeout, updated_at 은 **signup_consent_items 에 공용 트리거를 붙이지 않고** save 함수가 clock_timestamp() 로만 정함, NOTIFY pgrst, 되돌리기 파일, 끝에 VERIFY 블록 — 표 권한·정책·함수 실행 권한·'(3a) PUBLIC/anon 실행 SECURITY DEFINER 는 handle_new_user 뿐' 검사 포함)
### 2-1. `signup_consent_items` (현재 상태)
id uuid PK · key text unique not null default gen_random_uuid()::text(첫 값은 명시, 코드는 key 를 쓰지 않음 — 기록·운영 식별용, 변경 금지 트리거) · label text not null(공백 규칙 기준 빈값 금지, 접두어 "[필수]/[선택]" 금지 CHECK) · content text not null default '' · required boolean not null · policy_slug text null · **required_lock boolean null**(null=관리자가 바꿀 수 있음, true=항상 필수·숨김 불가, false=항상 선택 — 첫 값으로만 정하고 관리 화면에서는 못 바꿈) · sort_order int not null default 0 · is_active boolean not null default true · version int not null default 1 CHECK(version >= 1) · created_at, updated_at
- CHECK: `NOT required OR consent_normalize_text(content) <> ''`(필수 항목은 자체 요약문 필수 — 연결 약관이 꺼져도 빈 동의가 되지 않게), `required_lock IS NULL OR required = required_lock`, `NOT (required_lock IS TRUE AND NOT is_active)`.
- 새 항목은 is_active=false 로 만들어 미리 본 뒤 켬(save 함수가 p_id NULL 이면 강제).
- 트리거: key·required_lock 변경 금지, version 감소 금지.
### 2-2. `signup_consent_item_versions` (버전별 원문, 추가만)
PK(item_id, version) · item_id → items(id) RESTRICT · label, content, required, policy_slug(그 버전의 사본) · note text null(개정 사유) · created_at not null default now()
- 수정·삭제·TRUNCATE 금지 트리거. 항목이 처음 생기거나 version 이 오를 때 같은 함수 안에서 함께 기록.
### 2-3. `user_consents` (동의 기록, 추가만)
id uuid PK · **seq bigint generated always as identity**(최신 판정 기준) · user_id → profiles(id) ON DELETE CASCADE · (item_id, item_version) → item_versions FK · agreed boolean not null · source text not null CHECK in ('email_signup','kakao_signup','consent_gate','mypage') · created_at timestamptz not null default clock_timestamp()(잠금 대기 뒤에도 seq 순서와 시각이 맞게)
- 인덱스 (user_id, item_id, item_version, seq desc), (item_id, item_version).
- UPDATE·TRUNCATE 금지 트리거. DELETE 는 BEFORE DELETE 트리거로 '부모 profiles 행이 이미 없을 때(=탈퇴 CASCADE)'만 허용. 트리거 함수는 SECURITY DEFINER 로 만들지 않음(연쇄 삭제는 참조 표 소유자 권한으로 실행되어 DEFINER 가 필요 없음; DEFINER 로 만들 경우엔 REVOKE 로 3a 통과 — 선례 keep_admin_owner).
- 탈퇴: 결제 없는 회원은 CASCADE 로 지움(개인정보보호법상 지체 없는 파기). 결제 회원은 payment_orders RESTRICT 로 profiles 가 남아 기록도 남음. 10번 묶음(결제 회원 익명화)에 "동의 기록 보존·처리" 인계.
### 2-4. 표·함수 권한
- `user_consents.seq` 시퀀스도 `REVOKE ALL ON SEQUENCE … FROM PUBLIC, anon, authenticated, service_role`(setval 로 최신 판정이 흔들리지 않게), VERIFY 에 시퀀스 권한.
- 작업 기록 종류 `signup_consent_item_save`·`signup_consent_item_revise`·`signup_consent_texts_update` 를 `src/lib/admin-audit-log.ts` 의 ADMIN_AUDIT_ACTIONS 에 추가.
- 세 표: ENABLE RLS, REVOKE ALL FROM PUBLIC, anon, authenticated, service_role → **service_role 에 SELECT 만**. 쓰기는 아래 함수(소유자 postgres, SECURITY DEFINER, `SET search_path TO 'public','pg_temp'`)로만.
- 함수마다 `REVOKE ALL ON FUNCTION … FROM PUBLIC, anon, authenticated, service_role` 후 필요한 역할에만 EXECUTE. VERIFY 에서 함수별 ACL 을 정확히 대조: 내부 함수는 `{postgres=X/postgres}`, `get_my_missing_required_consents` 는 authenticated 만, 나머지 쓰기·검사 함수는 service_role 만, 쓰기·판정 함수는 모두 prosecdef 이고 search_path 가 public, pg_temp(`is_internal_admin_account` 는 DEFINER 아님 — 대조 목록에서 따로).
### 2-5. 함수
1. `consent_missing_required(p_user_id uuid, p_submitted jsonb default '[]') returns setof uuid` (내부 공용, 실행 권한 없음): 활성 필수 항목 중 "이번 제출에서 agreed=true 도 아니고, 현재 version 의 최신(seq) 기록도 agreed=true 가 아닌" 항목. 판정과 기록 검사가 같은 규칙을 씀.
2. `record_user_consents(p_user_id, p_items jsonb, p_source)` (service_role) — 실제 기록은 내부 함수 `consent_record_internal`(실행 권한 없음)이 하고, 이 함수와 카카오 완료·가입 취소가 모두 같은 내부 함수와 **같은 잠금 순서**(① 회원 advisory 잠금 ② items 공유 잠금 ③ 필요할 때 profiles 행 잠금)를 씀(교착 방지): 시작 시 `pg_advisory_xact_lock(hashtextextended('public.user_consents:' || p_user_id::text, 0))`. items 쓰기 잠금을 **공유 모드**로도 잡음(`pg_advisory_xact_lock_shared(hashtextextended('public.signup_consent_items:write',0))`) — 저장·개정과 겹치지 않게. **profiles 가 `provider='kakao' AND signup_completed=false` 이면 consent_gate·mypage 출처를 `CONSENT_KAKAO_SIGNUP_INCOMPLETE` 로 거절**(③ profiles 행 잠금 안에서 판정 — 이 상태의 기록은 complete_kakao_signup_with_consents 에서만 생김). source 'mypage' 는 선택 항목만 받고(필수는 거절) **필수 누락 검사를 건너뜀**, agreed=false(철회)는 숨긴 항목에도 받음(현재 version 으로 기록). source 'email_signup' 은 함수 안에서 **미인증 계정(auth.users.email_confirmed_at IS NULL)이고 profiles.provider = 'email' 일 때만** 받음. 그 회원의 기록이 하나도 없으면(첫 가입) 제출값 전체를 기록. 이미 기록이 있으면(같은 이메일 재가입 — 제3자일 수 있음) **선택 항목을 agreed=false 로 바꾸는 것만** 받고, true 로 올리거나 필수를 다시 쓰는 것은 건너뜀(서버 로그만). 인증된 계정·카카오 계정이면 건너뜀. p_source='kakao_signup' 은 이 함수가 받지 않음(카카오 완료 함수 안에서만 생김). p_items 형식(배열, item_id·version·agreed, item_id 중복 없음) 검사 → 각 항목이 활성이고 현재 version 과 같은지(`CONSENT_ITEM_CHANGED`) → **필수 항목은 모든 출처에서 agreed=true 만 받음**(false 면 `CONSENT_REQUIRED_MISSING`) → 1번으로 누락 필수가 있으면 `CONSENT_REQUIRED_MISSING` → 같은 (user,item,version) 의 최신 기록과 agreed 가 같으면 건너뜀 → INSERT. 결과로 **제출한 각 항목의 최신 기록(agreed, created_at)** 을 건너뛴 경우까지 포함해 돌려줌(처리 결과 안내용).
   - 사전 검사용 `consent_validate_submission(p_items) returns text` (service_role): record 와 같은 규칙(형식·버전·필수, 회원 기록 없이 제출만 보고)을 SQL 하나로 — 이메일 가입이 signUp 전에 부름(TS 에 규칙을 복제하지 않음).
3. `get_my_missing_required_consents() returns setof uuid` (authenticated): auth.uid() 가 NULL 이면 오류. **profiles 행이 없으면 `CONSENT_PROFILE_MISSING` 오류**(탈퇴 도중 실패 등) — 미들웨어는 통과, /consent 는 로그아웃 안내, 돈 API 는 403 `CONSENT_PROFILE_MISSING`(동의 화면으로 보내지 않음). auth.users 이메일이 `is_internal_admin_account` 면 빈 결과(is_admin 은 보지 않음). 아니면 1번(제출 없음).

## 3. 흐름
### 3-1. 미들웨어 판정(화면 이동용, 실패하면 통과)
- 대상: 로그인 회원의 **GET·HEAD 요청이고 Next-Action 헤더가 없는 것**. 관리자 ID 계정(user.email 내부 도메인)은 건너뜀(권한 해제된 관리자 ID 도 화면은 통과, 돈 API 에서는 막힘 — 의도).
- 위치: 판정 함수 `checkConsentGate(supabase, request, user)`(이미 받은 user 를 넘겨 getUser 를 다시 부르지 않음, RPC 는 `AbortSignal.timeout(1500)` 으로 끊고 통과) 하나를 **두 곳**에서 부름 — 카카오 분기 안의 "가입 완료" return 직전, 그리고 try 안 카카오 블록 바로 뒤의 공통 경로. 대상 조건은 `user && verifiedUserId`(3시간 만료로 끊긴 요청 제외). 미완료 카카오 회원은 카카오 가입 단계가 우선. **레이아웃 게이트는 두지 않음**(실제 강제는 돈 API).
- `Next-Router-Prefetch` 요청은 판정하지 않음(비용).
- 제외 경로(순수 함수 + 표 테스트, 원래 경로와 과목 접두어를 뗀 경로 둘 다로 판정): `/consent`, `/login`, `/signup`, `/forgot-password`, `/reset-password`, `/auth/*`, `/terms`·`/terms/*`, `/api/*`, `/admin`·`/admin/*`, `/dashboard/admin/*`(관리자 기능 화면), `/preview/*`, `/checkout/*/result`, `/mypage/withdraw`, `/mypage/payments`·`/mypage/credits`·`/mypage/support`(동의하지 않는 유료 회원의 결제 내역·크레딧 환불·문의 경로, 과목 접두 포함 — 환불 API `/api/refunds/request` 는 판정 대상 아님), `/library`(과목 접두어 포함 — 이미 산 자료는 동의와 상관없이 계속 받음, 다운로드 API 도 판정하지 않음), `/mypage/consents`(선택 동의 관리 — 필수 재동의 전·거부한 회원도 마케팅 철회 가능), `/_next/*`, `/__nextjs*`, `/.well-known/*`, public 파일 확장자(이미지·csv·hwpx·txt·pdf·json·ico 등). (옛 화면 `/legacy/*` 를 다시 켜면 `/legacy/mypage/withdraw` 추가 — 메모)
- 이동: `request.nextUrl.clone()` 의 pathname 을 `/consent` 로, search 를 비운 뒤 `searchParams.set('next', pathname+search)`(`_rsc`·`provider`·`signup` 제거 — **`login=success` 는 남김**: 로그인 복귀 담기·구매 의도가 동의 뒤에도 이어지게. next 안에만 들어가므로 /consent 화면에는 로그인 완료 창이 뜨지 않음)로 만든 **절대 URL** 로 redirect(상대 주소는 미들웨어에서 예외 → 판정이 조용히 꺼짐). 테스트는 updateSession 을 실제로 실행해 Location 을 확인 + **`copyResponseCookies(response, redirect)` 로 갱신된 세션 쿠키·만료 표시 쿠키를 옮김**.
- RPC 오류·예외는 잡아서 로그만 남기고 통과(바깥 catch 가 로그인 쿠키를 지우지 않게 판정 함수는 던지지 않음).
- 카카오 미완료 분기: `/terms`·`/terms/*` 는 리다이렉트하지 않음(약관 전문을 보고 동의).

### 3-3. 동의 UI(가입·카카오·동의 화면 공용 컴포넌트 하나)
- **고지 본문 강조 표기**: 본문은 일반 텍스트에 최소 표기 `**…**` 만 지원하는 렌더러로 보여 줌(굵게+밑줄, 다른 글보다 20% 이상 크게, HTML 은 모두 이스케이프). 첫 값에서 privacy 의 보유 기간, marketing 의 '새 자료·이벤트를 안내하려고 연락할 수 있다'는 목적을 강조 표기로 감쌈. 강조된 문장은 '보기'를 펼치지 않아도 보이게. 순수 함수 테스트: 강조 → strong/u, 이스케이프.
- 항목별 체크, 화면이 required 로 "[필수]/[선택]" 표시, 선택은 처음 해제, 고지 본문 "보기" 펼침, 연결 약관 새 창(문서가 없거나 꺼져 있으면 링크 숨김).
- 전체 동의: "선택 항목을 포함해 모두 동의", 처음 해제, 개별 해제 가능. 버튼은 켜 두고, 누르면 빠진 필수 항목을 강조(선택 미체크로도 가입 가능). 필수 항목의 요약문 첫 줄은 "보기" 밖에 보이게.
- **연결 약관 문서, 그리고 개인정보처리방침 문서(고정)를 불러올 수 없으면(읽기 오류·행 없음·문서 없음·꺼짐·빈 본문) "약관을 불러올 수 없습니다"로 가입·동의를 멈춤**(서버 제출 검사도 같은 확인). 선택 항목은 링크만 숨김. 이 판정은 **정규화하지 않은 원본**(`system_settings.site_footer_content` 행)을 읽는 전용 함수 `readRawPolicyDocument(slug)` 로 함 — 기존 로더는 빈 값·오류를 코드 기본 약관으로 바꾸므로 쓰지 않음. 규칙은 기존 정규화와 맞춤: slug → 문서 키 매핑은 코드 기본값(FOOTER_POLICY_DOCUMENT_DEFAULTS)으로, enabled 가 빠졌으면 켜짐으로 보고 '꺼짐'은 `enabled === false` 일 때만, 본문은 공백 규칙 기준 비었으면 '불러올 수 없음'. 행 없음·읽기 오류도 '불러올 수 없음'. 원본이 정상이면 /terms/[slug] 도 같은 DB 본문을 보여 줌(정규화는 비었을 때만 기본값을 씀).
- 제출: 화면이 받은 (item_id, version, agreed) 전부 — 체크 안 한 선택은 agreed=false 로 기록(다시 묻지 않음). `CONSENT_ITEM_CHANGED` 면 "항목이 바뀌었습니다. 다시 확인해 주세요" 와 함께 최신 항목으로 다시 그림.
- 선택 항목 처리 결과 안내(정보통신망법 결과 통지): 기록 직후(이메일 가입은 **제출값과 서버 시각**으로 만들어, 새 계정·이미 있는 이메일·미인증 기존 계정 세 경우 응답 모양과 안내가 같음 — 기록 여부·건너뜀은 응답에 넣지 않고 서버 로그에만; 계약 테스트로 고정) **이메일 가입 화면은 '처리 결과' 틀을 쓰지 않고 세 경우에 똑같이 참인 접수 문구 `optionalReceiptTemplate`**(예: "선택하신 내용({항목}: {결과})은 이메일 인증을 마친 새 계정에 반영됩니다. 처리 결과는 로그인 뒤 마이페이지 > 선택 동의 관리에서 확인할 수 있습니다.")를 보여 주고, 정식 "{전송자} {항목 이름} 처리 결과: 동의함/동의하지 않음 · {처리 일자}" 는 실제 기록이 있는 화면(/consent·/mypage/consents·카카오 완료 — DB 값)에서만 보여 줌(계약 테스트: 이메일 가입 응답에 처리 결과 틀이 쓰이지 않음). 전송자 = 사이트 기본 정보(상호명, 없으면 사이트 이름 — DB 값). 틀은 `optionalResultTemplate`. `/mypage/consents` 에서 항목별 최신 처리 결과(결과·일자)를 언제든 다시 볼 수 있음.
### 3-4. 이메일 가입
- 가입 화면 = 서버 page(항목 읽기, 서비스 롤) + 기존 클라이언트 화면.
- 서버 액션: 제출값을 함수 규칙과 같게 사전 검사(`CONSENT_*`면 계정 만들지 않음) → signUp → `identities` 가 비어 있으면(이미 있는 이메일) 기록하지 않고 지금처럼 성공 응답 (`identities` 가 undefined 여도 비어 있음으로 처리) → 그 밖에는 `record_user_consents(email_signup)` — 기록 조건은 함수가 판정(첫 가입이면 전체, 재가입이면 선택 철회만). 서버 액션도 `identities` 에 provider 'email' 이 있을 때만 기록을 부름. 성공 안내로 바꾸는 오류는 **회원별 재발송 간격 제한(메시지가 'you can only request this after' 형태)** 뿐(이미 있는 미인증 계정에서만 생김). 'Email rate limit exceeded'(프로젝트 전체 메일 한도 — 계정이 만들어지지 않음)를 포함한 그 밖의 오류는 실패로 돌려주고, 보이는 문구는 정해진 일반 안내. 순수 함수 표 테스트에 두 메시지. 한계 메모: 인증 전 기록이라 남의 이메일로 가입한 사람의 선택이 남을 수 있음(기록이 없는 기존 미인증 계정 — 배포 전 생성·공개 키 직접 가입 — 에는 제3자의 첫 제출 전체가 남을 수 있음). 다만 인증 전 계정은 로그인할 수 없고 실제 주인이 미인증 상태로 다시 가입하면 최신 선택이 반영됨. 미인증 계정 정리는 출시 조건 순서표. 공개 키로 signUp 을 직접 부르면 동의 기록 없이 계정이 생길 수 있음 — '가입 때 기록은 보장이 아니며 첫 로그인 게이트와 돈 API 가 받음'. 기록 실패는 로그만(첫 로그인 때 동의 화면이 받음).
### 3-5. 카카오 가입
- **동의를 카카오로 넘어가기 전으로 당김**: 가입 선택 화면(/signup 첫 화면)에 공용 동의 UI. 필수를 체크하지 않으면 카카오·일반 버튼을 눌러도 진행하지 않고 빠진 항목을 강조. 일반 가입은 같은 상태를 그대로 씀(두 번 받지 않음). 카카오는 제출값(item_id·version·agreed)을 sessionStorage 에 넣고 OAuth 로 넘어감.
- 확인 단계: sessionStorage 값으로 체크를 채워 회원이 다시 확인(값이 없으면 — 로그인 화면의 카카오로 처음 들어온 경우 — 빈 체크로 받음). 기록 시각은 확인 단계 제출 시각. 문구(DB): "가입을 마치기 전까지 카카오에서 받은 정보는 이용하지 않으며, 취소하면 바로 삭제됩니다."
- 확인 단계에 동의 UI. 기존 `PATCH /api/profile`(`complete_kakao_signup`) strict 스키마에 동의 배열 추가 → strict 스키마의 동의 배열은 **필수**(배포 중 옛 화면은 400 "화면을 새로고침한 뒤 다시 시도해 주세요"). 그 분기는 `complete_kakao_signup_with_consents` 하나만 부르고 응답 모양은 `{ profile, consentResults }`(profile 모양은 지금과 같음)(이미 완료면 지금처럼 profile 을 돌려줘 화면이 next 로 이동). 실패·필수 누락이면 완료하지 않고 오류. sessionStorage 동의값은 저장 시각·항목 version 과 함께 넣고, 30분이 지났거나 version 이 현재와 다르면 버림. 완료·가입 취소·이미 완료로 이동할 때 지움.
- 완료 뒤 바로 이동하지 않고 처리 결과 안내 단계(확인 버튼)를 한 번 보여 준 뒤 next 로 이동.
- **카카오 확인 단계의 모든 클라이언트 이동**(이미 완료일 때·안내 뒤·가입 취소 뒤)은 3-6절의 `safeConsentNext` 와 같은 공용 함수(`safeInternalNext`)를 씀. 미들웨어의 카카오 분기(`normalizeInternalPath`)와 인증 콜백의 `normalizeNext` 도 같은 공용 함수로(결과가 `//`·`/\` 로 시작하면 홈). 카카오 단계에서는 `/consent` 로 가는 next 를 허용(돈 API 403 → /consent → 카카오 단계 → 완료 뒤 원래 목적지 유지). 표 테스트에 카카오 단계 기준 `/.//evil.com`, `/%2e//evil.com`.
- "가입 취소": `POST /api/auth/cancel-signup`(/api 라 미들웨어 분기를 피함) → 출처 검사(기존 `isTrustedFormPostOrigin`) → 세션 user 로 `cancel_incomplete_kakao_signup` 통과 시 deleteUser 직전 한 번 더 확인 후 deleteUser → 응답에서 request 쿠키 중 `sb-` 로 시작하는 것 모두(분할 쿠키·code-verifier 포함)와 `sst-session-started-at` 을 지움 → 홈. 판정 뒤 결제가 생겨 지우지 못하면(RESTRICT) 정해진 안내. 완료 화면 문구(DB): "카카오 계정 설정에서 연결을 끊을 수 있습니다."
### 3-6. 동의 화면 `/consent` ((auth) 그룹)
- (아래 '관리자 ID 계정 → 홈' 대신 RPC 빈 결과 → next 로 통일)
- 상태: 로그인 여부는 다른 화면과 같게 `getRequestAuthUserId()`(미들웨어가 확인한 값, 3시간 만료 반영)로 판단 — 없으면 비로그인 → `/login?next=` 에 `/consent?next=…` 전체를 넣음(원래 목적지 유지). 관리자 ID 판정은 별도로 하지 않고 RPC 빈 결과에 맡김(빈 결과면 next 로). profiles 행이 없는 세션(탈퇴 도중 실패 등)은 RPC 가 정해진 오류 코드를 돌려주고 /consent 는 로그아웃 안내. /consent 화면은 profiles 를 서비스 롤로 읽어 미완료 카카오면 카카오 단계(`/signup?provider=kakao&signup=1&next=…`)로 보내고, 읽기가 실패하면 동의 UI 대신 '잠시 후 다시 시도'. 서버 액션이 `CONSENT_KAKAO_SIGNUP_INCOMPLETE` 를 받아도 카카오 단계로. 비로그인으로 /consent 에 왔다가 로그인해 `login=success` 가 /consent 주소에 붙으면, **/consent 서버 page 가 화면을 그리기 전에** 그 값을 next 안으로 옮긴 /consent 주소로 서버 `redirect()`(남은 next 는 safeConsentNext 로 검사, login 값이 있을 때만이라 반복 없음) — 전역 로그인 완료 창(src/app/template.tsx)이 /consent 에서 뜨거나 닫힐 때 값을 지우는 일을 막음. /consent·/consent 진입 때는 카카오 sessionStorage 동의값을 지움(카카오 단계에서는 읽은 뒤 완료·취소·이미 완료로 이동할 때 지움). 가입 취소 route 는 `getRequestAuthUserId()` 가 있고 세션 getUser().id 와 같을 때만 삭제. /mypage/consents 서버 액션도 user id 는 `getRequestAuthUserId()`. 그 밖에는 **미들웨어와 같은 RPC(사용자 세션)** 결과로: **성공 응답이 빈 배열일 때만** next(없으면 홈)로 이동. RPC 오류·배열이 아닌 응답이면 이동하지 않고 "잠시 후 다시 시도" 안내·다시 시도·로그아웃 버튼(왕복 루프 방지, 테스트로 고정). 선택 항목 기록은 서버가 서비스 롤로 세션 user id 만 걸러 읽음.
- 보여 줌: 부족한 필수 + 현재 버전 기록이 없는 선택(공용 UI). 개정이면 현재 버전 원문의 note 와 개정일.
- next 함수 구성: **기본 함수 하나**(고정 기준 origin·결과 재검사·`//`·`/\`·`\` 거절, /login·/signup·/forgot-password·/reset-password → 홈)를 로그인 화면·인증 콜백·카카오 단계·/consent 가 함께 씀. **/consent 화면에서만** 추가로 /consent·카카오 단계·/api·/auth 를 거절(로그인·콜백·카카오 단계는 /consent 허용 — `/login?next=/consent?next=…` 가 목적지를 잃지 않게).
- next 검사(`safeConsentNext`, 서버 이동과 클라이언트 이동 모두): 고정 기준 주소(`http://localhost`)로 `new URL(next, base)` 해석해 **origin 이 기준과 같은지 확인**(www/미리보기 배포와 무관)한 뒤 pathname+search+hash 만 씀 → 그 **결과**가 `/` 로 시작하지 않거나 `//`·`/\` 로 시작하거나 `\` 를 담으면 홈 → `/consent`(과목 접두어 포함)·카카오 가입 단계(쿼리 `provider=kakao&signup=1` 로 판정)·`/api`·`/auth` 로 가면 홈. 테스트: `/.//evil.com`, `/./\\evil.com`, `/%2e//evil.com`, `https://evil.com`, `/english/consent`.
- "동의하고 계속" → 서버 액션(user id 는 `getRequestAuthUserId()` — 3시간 만료와 기준 일치) → 기록 → 처리 결과 안내 → `safeConsentNext` 로 `window.location`.
- "동의하지 않음" → 확인 창("필수 항목에 동의하지 않으면 이용할 수 없어 로그아웃됩니다. 다시 로그인하면 이 화면이 나옵니다.") → 전용 **POST route `/api/auth/consent-logout`**(미들웨어 카카오 분기를 피하려 /api/auth 아래, `isTrustedFormPostOrigin` 출처 검사, signOut 결과와 상관없이 응답에서 request 쿠키 중 `sb-` 로 시작하는 것 모두와 `sst-session-started-at` 을 지움 — 테스트로 고정) 로그아웃(**지금 기기만**, `signOut({ scope: 'local' })` — 서버 액션은 응답 뒤 화면을 다시 그려 이동이 꼬일 수 있어 route 사용, 기존 /api/auth/logout 은 건드리지 않음) → `window.location` 홈. 버튼 이름 "지금은 동의하지 않고 로그아웃". 서버 로그아웃 뒤 곧바로 `window.location.replace`. 확인 창에 "로그아웃 상태로 둘러보기는 계속할 수 있습니다". 화면에 "선택 동의 관리"(/mypage/consents), "자료 보관함(구매한 자료)"(/library), "크레딧 관리·환불"(/mypage/credits), "결제 내역"(/mypage/payments), "1:1 문의"(/mypage/support), "탈퇴하기"(/mypage/withdraw) 링크와 고객센터 연락처(하단 정보 값).

- 순수 함수: 제외 경로·메서드·헤더 표, next 검사(`//`·`/\`·`/consent`·`/api` 거절, `_rsc` 제거), 제출값 사전 검사.
