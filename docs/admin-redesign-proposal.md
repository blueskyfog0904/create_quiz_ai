## 1. 요약

**현재 상황 진단**
1. 현재 디자인 사이트는 사실상 "국어 문제마켓(자료 판매) + 크레딧 충전 + 마이페이지"다. AI 문제생성·문제은행·지문·시험지는 공개 진입 링크가 없다(R1 §0-1, R2 F1·F2).
2. 관리자 사이드바 30개 메뉴가 한 평면 목록이고(`src/lib/admin-sidebar.ts:77-107`), 과목과 무관한 메뉴(회원·결제·문의 등)까지 모든 링크에 `?subject=`가 붙는다(`admin-sidebar-client.tsx:62`). 과목은 사이드바 상단 [영어|국어] 토글로 바꾸고 값이 없으면 영어다(R2 §1).
3. 실제로 과목에 따라 데이터가 달라지는 운영 메뉴는 7개(상품·카테고리·게시판 메뉴·홈 광고·홈 구성·출처·후기)뿐이고, 나머지 운영 메뉴는 과목 무관이다(4-1절 전수 분류).
4. 기능 결함: 대시보드 지표 상당수가 무의미(매출 항상 0 포함), 회원 목록 20명 한계, 메뉴관리의 "문제마켓 그룹"은 테이블이 없음, 인증 가드 3방식 혼재(5절).
5. 디자인: Studio 토큰 사용 0건, tailwind 기본 팔레트 842회, 머리말 6변형, `alert/confirm` 43회, 44px 준수 7/88 파일, 사이드바 slate+orange(R3 §0·§1·§4).
6. 현재 화면에서 과거 화면으로 새는 링크 3곳(1곳은 섹션 삭제로 별도 해결 중), `/checkout` 과거 헤더·푸터, `/pricing` gray 스타일(R1 §0-2·§0-3, #12).

**제안 핵심 5개**
1. 사이드바를 **공통 / 과목별(국어·영어) / 레거시** 세 영역으로 나눈다. 과목 메뉴는 "국어 ▸ 상품 관리"처럼 과목을 1단계 그룹으로 펼쳐 링크 자체가 과목을 가리키게 하고(4-2절 옵션 B), 공통 화면에는 과목 전환 UI를 보이지 않는다.
2. 기본 과목을 없앤다. 관리자는 공통 대시보드로 들어가고, 과목 화면은 항상 URL `?subject=`로 과목이 정해진다. 과목 없이 열린 운영 과목 화면(7개)은 조용히 영어로 열지 않고 과목 선택을 요청한다. 레거시 화면은 코드를 그대로 두고, 메뉴 링크에 과목을 담는다.
3. 메뉴 구성(그룹·순서·숨김)은 `system_settings` 키 `admin_sidebar_navigation` 1행에 저장하고, 코드에는 페이지 등록부(경로·이름·아이콘·공통/과목 구분)와 정규화 규칙만 둔다(CLAUDE.md 2.5절). 과목 메뉴 순서는 두 과목 공통 1벌.
4. 먼저 **P0 결함**(대시보드 지표, 회원 20명 한계, 없는 테이블을 쓰는 카드, 새는 링크, `/checkout` 크롬)을 고친다(Phase 1a). 디자인은 새 테마 없이 Studio를 그대로 쓰고, 공용 부품은 실제 소비처 2곳 이상만 만든다(R3 §7).
5. 레거시 화면은 삭제·디자인 이관 없이 레거시 그룹에서 그대로 동작하게 둔다. 레거시 페이지 코드는 바꾸지 않으며, 유일한 예외는 보안·가드 정리(P1-1)다. 삭제 여부는 나중에 결정한다.

### 4-2. 과목 전환 방식 비교

현재 방식: 사이드바 상단 토글이 URL `?subject=`를 바꾸고(`admin-workspace-switcher.tsx:25-27`), 모든 사이드바 링크에 `?subject=`가 붙는다. 같은 토글이 홈 광고·홈 구성 화면 안에도 있다(`main-ad-settings-client.tsx:384`, `market-main-settings-client.tsx:151`). 공통 화면에서도 토글이 보여 "지금 고른 과목이 이 화면에 영향을 주는지" 알 수 없다.

| 기준 | A. 사이드바 "공통" 섹션 + "과목" 섹션(섹션 머리에 국어/영어 전환) | **B. 과목을 1단계 그룹으로 펼침("국어 ▸ 상품 관리…", "영어 ▸ …")** | C. URL 경로 `/admin/{subject}/...` |
|---|---|---|---|
| 현재 과목 인지 | 섹션 머리 전환 상태를 봐야 함 | 메뉴 자체가 과목을 가리킴 + 활성 항목이 "국어" 그룹 아래 | 주소에 과목이 보임 |
| 과목 바꾸기 | 전환 1클릭 후 메뉴 클릭 | 다른 과목 그룹의 메뉴 1클릭(또는 화면 머리말의 "영어로 보기") | 다른 과목 메뉴 1클릭 |
| 공통 화면에서 과목 상태 | 과목 섹션 링크가 어느 과목을 가리킬지 **기억된 과목이 필요**(D2 "기본 과목 없음"과 충돌, 새 저장소 필요) | 필요 없음(링크마다 과목 고정) | 필요 없음 |
| URL·딥링크·새로고침 | `?subject=` 유지로 문제 없음 | 동일 | 경로라 가장 명확 |
| 다른 과목 실수 수정 위험 | 중간(전환 상태를 놓치기 쉬움) | 낮음 | 낮음 |
| 기존 `?subject=` 링크 호환 | 그대로 | 그대로 | 리다이렉트 필요 |
| 사이드바 길이 | 짧음(과목 메뉴 7개 1벌) | 과목 메뉴 7개 × 2 = 14줄. 현재 화면의 과목 그룹만 펼치고 나머지는 접어 완화 | 짧음(B와 같은 사이드바가 필요하면 B와 동일) |
| 구현 규모(추정) | 사이드바 + 과목 기억 저장소(쿠키 등) 5~8파일 | 사이드바 렌더 + 설정 형식 + 머리말 과목 표시 5~8파일 | 과목 페이지 7개 + 레거시 과목 페이지 폴더 이동, 링크·리다이렉트·미들웨어 30파일 이상 |

**권장: B.** 과목이 2개뿐이라 메뉴를 두 벌 펼쳐도 길이 부담이 작고, 링크가 과목을 직접 담아 "숨은 현재 과목" 상태가 없다. 기본 과목을 두지 않는다는 결정(D2)과도 바로 맞는다. C는 같은 효과를 내지만 라우트 이동 비용이 크고 이득은 주소 표시뿐이다.

B의 세부 규칙:
- **공통 화면**: 링크에 `?subject=`를 붙이지 않고, 과목 전환 UI·과목 배지를 표시하지 않는다(사이드바 상단 토글 제거).
- **과목 화면**: 머리말(`AdminPageHeader`)에 현재 과목을 과목색 + 텍스트로 항상 표시한다(국어 emerald, 영어 blue, DESIGN.md Brand). 같은 머리말에 "영어로 보기"처럼 같은 화면을 다른 과목으로 여는 전환을 둔다(현재 스위처의 "경로 유지 + subject만 교체" 동작 재사용). 홈 광고·홈 구성 화면 안의 개별 토글은 이것으로 대체한다.
- **과목 없이 열린 운영 과목 화면**(7개, 옛 북마크 등): 영어로 조용히 열지 않고 "국어 / 영어 중 선택" 안내를 본문에 표시한다. 기존 `resolveAdminWorkspaceSubject`는 값이 없으면 `english`를 돌려주므로(`admin-workspace.ts:5-7`) 이 판단에 쓸 수 없다. 화면용으로 **값이 없거나 잘못되면 `null`을 돌려주는 해석 함수**를 `admin-workspace.ts`에 새로 두고, 운영 과목 화면 7개의 page가 이것으로 과목을 읽어 `null`이면 선택 안내 헬퍼를 그린다(소비처 7곳). 기존 함수와 API 기본값은 그대로 둔다.
- **저장 확인 문구에 과목명 포함**(예: "국어 홈 광고를 저장했습니다"). 기존 토스트 문구만 바꾸는 수준.
- **레거시 화면은 페이지 코드를 바꾸지 않는다**(6-6, 요약 5번, 예외는 P1-1 가드·admin 확인뿐). 선택 안내 헬퍼·머리말 과목 표시도 적용하지 않는다. 사이드바 토글이 없어지므로, 과목을 쓰는 레거시 화면은 **메뉴 링크가 과목을 담는다**(4-4의 레거시 항목 `subject` 값). 링크에 과목이 없으면 기존 코드대로 영어로 열린다(현재 동작 유지).
- 레거시 과목 화면의 과목 지정(직접 확인, 테이블별 `workspace_subject` 행 수 SELECT):

| 레거시 화면 | 국어 데이터 | 링크 |
|---|---|---|
| 문제생성 상품(`generate_listboard_posts` 18, `generate_menu_entries` 5), AI 문제 유형(`problem_types` 10), AI 생성 로그(102), 문제은행 5종(`questions` 81, `question_bank_years/books/problem_types` 1/1/11) | 0건(모두 english) | `?subject=english` 1개 |

### 4-4. 저장 구조 (하드코딩 금지 규칙 반영)

현재: 이름·아이콘·기본 순서·문제은행 그룹이 코드(`admin-sidebar.ts:52-58, 77-107, 132-161`), DB에는 `workspace_settings`에 과목별 href 순서만(직접 확인: english 1행 17개, korean 행 없음). `workspace_settings.workspace_subject`는 NOT NULL이라 과목 무관 설정을 둘 수 없다.

- **코드(규칙)**: 페이지 등록부 = href → 이름·아이콘·exact·`scope: 'common' | 'subject'`. scope는 4-1절처럼 페이지가 과목을 쓰는지에 따른 코드 성질이라 코드가 소유한다. 과목 목록(`korean`, `english`)도 기존 `WorkspaceSubject` 타입 그대로. 메뉴 이름의 출처는 등록부 하나뿐이고 DB에 이름 덮어쓰기를 두지 않는다("(임시)" 제거는 등록부 수정).
- **DB(데이터)**: `system_settings` 키 `admin_sidebar_navigation` 1행(컬럼 `key, value, description, updated_at`, 직접 확인). 값 형식 예:

```json
{
  "common": [
    { "id": "top", "name": null, "items": ["/admin", "/admin/market/images"] },
    { "id": "members", "name": "회원·고객", "items": ["/admin/users", "/admin/support"] }
  ],
  "subjectOrder": ["korean", "english"],
  "subjectItems": ["/admin/market/products", "/admin/market-categories"],
  "legacy": {
    "name": "레거시",
    "items": [
      { "href": "/admin/landing-pages" },
      { "href": "/admin/menu-management", "subject": "korean" },
      { "href": "/admin/menu-management", "subject": "english" },
      { "href": "/admin/problem-types", "subject": "english" }
    ]
  },
  "hidden": []
}
```

  - `name: null` 그룹은 1단계 메뉴로 바로 표시. 그룹 이름·순서·과목 순서·숨김은 모두 데이터.
  - **과목 메뉴 순서는 공통 1벌**(`subjectItems`)을 각 과목 그룹 아래에 똑같이 그린다. 과목 화면이 두 과목에서 같은 페이지이고, 과목별 순서를 따로 두면 지금처럼 두 과목 순서가 어긋난다(R2 §5).
  - **레거시 항목의 `subject`는 데이터**다. "어느 과목에 레거시 데이터가 있는가"는 데이터 사실이라 코드 규칙으로 고정하지 않는다(CLAUDE.md 2.5절). 메뉴 이름 뒤 " · 국어/영어" 표기는 같은 href가 두 번 나올 때만 붙이는 등록부 규칙이다.
- **정규화 규칙**: DB에 없는 등록 페이지는 scope에 따라 공통 끝 "미분류" 그룹 또는 `subjectItems` 끝에 자동 추가. scope가 `common`인 페이지가 `subjectItems`에 들어 있으면 무시(데이터 오류로 공통 화면에 과목이 붙지 않게). 레거시 항목은 href + subject 쌍으로 중복을 판단하고, `subject`가 없으면 과목 없는 링크로 그린다(레거시 페이지가 기존 코드대로 영어로 엶). 어떤 페이지가 레거시인지는 DB 데이터로만 정해지므로, 데이터 스크립트가 레거시 페이지 전부를 `legacy`에 넣는다(계약 테스트로 확인). 읽기 순서는 새 `system_settings` 행 → 없으면 기존 `workspace_settings` english 행(`{items}`)을 "그룹 없음"으로 → 없으면 코드 기본 순서. 새 행 입력·확인 후 기존 english 행은 정리.
- 4-3 트리는 **데이터 스크립트로 입력**한다(개발 DB 직접 작업 가능, 메모리 "Supabase는 개발 DB"). 코드 상수로 트리를 넣지 않는다. 하드코딩된 `ADMIN_QUESTION_BANK_MENU_HREFS`(`admin-sidebar.ts:52-58`)는 제거 대상.
- "관리자 메뉴 구성" 화면: 지금의 위/아래 이동에 그룹 간 이동·숨김 토글만 더한다(드래그 없음).

## 9. 한계

- **브라우저 화면 확인을 하지 않았다**(서버 미실행 조건). 모든 판단은 코드·DB SELECT 기반이다(R3 §3, §8).
- **접속 로그가 없다**. "레거시·고아" 판정은 공개 링크·코드 참조 기준의 **추정**이다(R2 §7).
- 4-1 분류의 (가)는 문자열 grep 수치라, 과목을 다른 이름으로 다루는 코드가 있으면 누락될 수 있다. 공통으로 분류한 화면은 페이지 코드와 테이블 컬럼 두 근거가 모두 "없음"인 것만 넣었다(환불은 테이블 1개에 컬럼이 있으나 페이지가 전체 조회).
- 예상 변경 규모(7절)는 추정이며 Phase별 상세 계획서에서 확정한다.
- R1·R2 수치가 다른 항목(영어 상품 R1 공개 1 / R2 전체 2, `alert/confirm` 집계)은 집계 범위 차이로 보고 R3 범위(관리자 88파일)를 따랐다.
